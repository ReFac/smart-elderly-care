# 照护时间线

[文档导航](README.md)

「照护业务 → 照护服务 → 照护工单」用于逐人办理待执行任务。「已完成服务」将同类执行记录按时间排列，支持搜索服务项目、长辈、执行人或房间。可选某个日期或近 60 天。展开任意一组即可核对每笔工单的编号、长辈、执行人、备注、计划时间和床旁核验，再打开工单凭证进行服务抽检。

## 长辈与房间的设置

| 入口 | 设置范围 |
| --- | --- |
| 入住管理 → 选择长辈 → 照护时间线 → 显示设置 | 只改变该长辈档案内的分组；详细档案也有同一条时间线。 |
| 房间工作台 → 选择房间 → 房间照护记录 → 显示设置 | 只改变该房间内的分组。房号相同的不同分院和楼栋使用独立的房间编号。 |
| 照护服务 → 已完成服务 | 同时遵从每笔工单所属长辈与房间的设置。任一方选择逐笔展示时，该工单单列；两边都合并时，取较短的窗口。 |

具有照护权限且获准访问相应长辈或房间的员工可调整显示设置。默认按 30 分钟合并，可选 10、15、30、60 分钟或逐笔展示。点击「保存显示设置」并确认后，页面回到同一对象。档案和房间的「最近改动」另开对应范围的变更历史，可查看设置的经办人和说明。家属及长辈自助端继续依照原有服务授权查阅。

## 如何判断一组记录

1. 直接登记、床头卡核验和语音申请人工确认后，服务端同时登记实际提交完成的时刻、执行账号和当时的床位、房间。即时记录按上海时区展示；旧凭证只有日期时会显示「时刻未登记」，计划时间仍可在明细中核对。没有可核验床位的历史工单保留在授权的长辈或机构工单视图中。
2. 新建工单时，在「完成后时间线归类」可选择饮水照护、用餐陪护、按标准服务名称或单独展示。标准名称包括「递水」「协助饮水」「午餐陪护」等。实际备注中出现呛咳、拒绝、跌倒等需关注情形时，工单单列。医嘱执行、巡视及未归类的其他项目逐笔展示。
3. 只合并同一天、同一执行房间、同类日常服务、有精确时刻和执行账号的工单。窗口从这一组的第一笔开始。例如 09:00、09:12、09:24 的递水记录可合并为 09:00–09:24；09:35 另起一组。摘要展示参与的员工和长辈；每位员工为哪位长辈提供了哪项服务可由逐笔明细核实。
4. 转床后，既有凭证仍指向执行当时的房间。分院或限定房间的员工只能看到同时满足当前长辈授权、历史执行位置授权的记录。不同长辈、房间显示方式的变更不影响原始工单、审计及业务统计。

## 接口

在「照护服务 → 集体活动」选择分院、房间和实际日期，登记三餐或其他集体活动。活动结束后，护士长或获授权员工打开铃铛的「集体活动待确认」，逐人核对默认全选的名单。未参加者没有出席记录；当餐供应的菜品与个人实际食用的品种、份量可分别登记。档案的「生活时间线」按活动发生时的房号、日期和时间查看，可调整截止日期回看过往一周。

`GET /api/daily-life/roster` 按经办权限、院区、房间和日期返回候选名单。使用 `care.proposeGroupActivity` 提交登记，经授权使用 `care.confirmGroupActivity` 签认。`GET /api/residents/{id}/daily-life?start=YYYY-MM-DD&end=YYYY-MM-DD` 返回该长辈在所选日期内参加过的已确认活动。批次与每位参与者的记录一同保存在机构加密备份。

`GET /api/care-timeline/work`、`GET /api/care-timeline/resident/{id}` 和 `GET /api/care-timeline/room/{id}` 共用 `day`、`q`、`offset`、`revision` 筛选。翻页传入首屏返回的版本，如其间有人提交新业务，重新读取第一页。修改通过带版本与操作说明的 `care.timelineSettings` 命令提交。
