# 机构完整快照与异地恢复

[文档导航](README.md)

总管理员打开「系统管理 → 机构设置 → 备份与恢复」，即可导入、导出、核验或恢复加密备份。恢复点按时间分页，可区分定时快照、手工快照、导入文件以及恢复或更新前的保护点。[机构服务版本更新](updates.md)

## 导出和导入文件

1. 在目标恢复点点击「导出」，确认所选范围后，浏览器下载完整的 `.akbak` 密文。下载授权仅当前总管理员会话可用，3 分钟内限用一次。
2. 点击「导入备份」并选取本机构文件。服务器分块接收文件，在私有临时目录校验认证标签、加密数据库页、业务库和机构编号。页面展示业务版本、长辈、员工、原件数量及差异。导入预览保留 30 分钟。
3. 选择「导入快照库」并确认，原文件按摘要核对后登记在恢复点清单内。同一密文重复导入复用已存在的有效恢复点。只登记文件时，机构仍在原业务版本上工作。

## 应用与回退

在恢复点上点「恢复」，先看它与当前业务库有哪些差异。点击「应用到当前工作库」并再次确认后，服务器核对操作人、文件、所属机构、预览版本和有效期。若期间有人提交了变更，请重新打开预览。核对通过后，服务器保存当前完整加密保护点，再用一个数据库事务提交新的业务修订。每次应用都有独立记录和备注，旧记录仍可查阅。

在线恢复覆盖照护及运营工作数据、机构结构、长辈及亲属档案。当前有效的账号与授权、套餐用量、设备确认、审计和运行会话由原工作库持续管理。如果旧时间点会撤回已完成的护理、支付回执、用药、签认或原件，页面逐项列出冲突。涉及这类差异时，可将完整加密包恢复到独立目录进行查阅，流程见下方灾备命令。每份可独立恢复的完整包亦含当时的账号与授权。

要回退这次恢复，可从「最近改动」打开对应记录，或在恢复点清单选择「恢复前保护点」。核对差异并确认后，系统发布一个新修订，同时记录两次操作的关联。网页恢复使用本机构的部署密钥。如果原主机已丢失，可用离线密钥把整个机构库还原到新的私有目录。

## 设置与保留策略

「备份设置」包含本机完整快照保留期、导入文件上限和机构异地配送位置。默认长期保留；也可选择 60、90、180、365 天。导入上限支持 64、256、1024、4096 MiB，默认 1024 MiB。反向代理应允许所需的请求大小及超时。超出网页上限的完整包可用下方恢复命令处理。

本机副本达到保留期后，系统会核对异地位置是否仍获授权、该快照最近一天内是否有完整回读证明，以及是否已有更新的可恢复点。这些条件都满足，才释放本机副本。证明过期时，系统先重新配送并回读。释放后可在该行点「从异地取回」，校验通过后重新计算本机保留期。停止向某个位置配送时，已送达的密文仍然保留。变更记录另有固定的 60 天回溯窗口。

## 压缩与旧备份

新导出的 v2 加密包在独立 SQLCipher 副本内无损压缩业务 JSON、档案资料和巡查简报，随后回收空闲页。原工作库保持在线，临时文件也使用加密数据库。医疗图片等原件逐字节保留。列表显示快照大小；体积缩小时显示本次实际节省比例。照片和音视频占比高时节省比例会较小。每个时间点均可独立还原，导入继续接受既有 v1 包。恢复时先验证整个包，再还原文本和核验数据库。

## 时间与覆盖范围

系统每天北京时间 00:00 创建一份可独立恢复的全量快照。首次运行会为当前时段创建恢复点。主机错过一个或多个时段时，会在重新上线时保存当时的数据，页面标明实际捕获时间。

快照收录所有分院已提交的账号和授权、员工和长辈档案、护理及财务数据、识别与审核记录，以及已归档的医疗图片、已导入的环境原件和历史附件。外部素材只保留网址。需要随快照恢复的环境图片，请先导入机构媒体库。[原件入库与存储格式](storage.md)

本机目录默认为工作库同目录下的 `workspace.sqlite3.snapshots/`。系统生成的 `.akbak` 是经过认证的密文。每个已连接的目标各有重试队列，收到完整远端文件、重新计算 SHA-256 并核对后才显示「异地已校验」。上传失败会保留本机恢复点，网络恢复后重试；管理员也可点「重试失败的备份」。网盘与本机的容量需要覆盖保留期内的全部完整副本。列表每页展示 50 个时间点，可点「更早的时间点」继续查阅。

## 常驻定时任务

运行服务时自带备份工作线程。Linux 部署还应安装用户级 systemd 定时器，保证应用进程和浏览器退出后仍能执行。请以运行业务服务的同一账号运行。后台服务需要额外环境配置时，在安装命令末尾加 `--environment-file /受保护目录/backup.env`，通过同一套系统凭据管理向 Web 服务和定时任务供给存储密钥及网盘授权。

```bash
python3 manage_backups.py --db .local/workspace.sqlite3 run-due
python3 manage_backups.py --db .local/workspace.sqlite3 install-timer
systemctl --user list-timers
```

部署管理员可用 `loginctl enable-linger 服务账号` 允许用户定时器在注销后继续运行。定时器在北京时间零点触发，并每隔 15 分钟检查积压任务。应用线程和主机定时器共享同一份幂等记录。其他系统可用原生任务计划程序每 15 分钟以同一账号运行上述 `run-due`，系统按固定时段去重。机器断电、磁盘写满或网盘持续不可达时，记录的最近成功时间反映实际恢复能力。最近快照显示「尚未接入位置」表示当前只有本机副本。

## 授权 iCloud、115、百度及其他异地存储

在部署端安装 rclone，试点已验证 v1.72.0。可将程序放在 `.local/backup-tools/rclone`、加入系统 PATH 或用 `NH_RCLONE_BIN` 指定。以服务账号执行 `rclone config`，为每个目标准备独立的专用目录与具有读写权限的账号。首次使用请在交互终端为 rclone 配置文件设置加密口令。定时任务通过服务账号的秘密管理器取得解锁口令，服务重启后也需要能非交互解锁。部署方保管账号认证及续期；总管理员在工作台选择哪些已授权位置可以接收本机构副本。[rclone 配置加密](https://rclone.org/commands/rclone_config_encryption/)

| 目标 | 部署与核对 |
| --- | --- |
| iCloud Drive | rclone 选择 `iclouddrive` 和 Drive 存储，用机构授权的 Apple 账号及双重认证完成登录。会话要求重新验证时，在部署机运行 `rclone config reconnect 远端名:`。[iCloud Drive 驱动](https://rclone.org/iclouddrive/) |
| 115 网盘 | 在机构私有 OpenList 上接入「115 开放平台」驱动，通过授权账号选择根目录，向备份服务开放该目录的 WebDAV 读写。每个销售部署使用机构各自获准的目录和授权，按 115 平台适用条款办理。[115 Open 接入](https://doc.oplist.org/guide/drivers/115_open) |
| 百度网盘 | 在机构私有 OpenList 中配置「百度网盘」，使用获准的应用及机构 OAuth 授权。配置通过网关代理下载，使超过 20 MiB 的副本也能由网关携带所需请求头回读。[百度网盘驱动](https://doc.oplist.org/guide/drivers/baidu) |
| 其他异地存储 | rclone 支持 WebDAV、SFTP、S3 等。为机构分配独立、可写且可完整回读的目录。首次接入可先用无个人信息的临时机构完成恢复演练。[WebDAV 驱动](https://rclone.org/webdav/) |

对私有网关，在 rclone 新建 `webdav` 远端，选择 `other`，URL 指向已部署的 HTTPS WebDAV 根（例如 `https://backup.example.org/dav/`），配置机构服务账号。在文件 `.local/platform/backup-locations.json` 登记已有对应远端的目录。以下名称均为示例。只填写已配置的目标。可用 `NH_BACKUP_LOCATIONS_FILE` 指定配置文件路径。

```json
{
  "icloud": "apple:Eldercare/Backups",
  "115": "openlist:115/Eldercare/Backups",
  "baidu": "openlist:baidu/Eldercare/Backups",
  "offsite": "second-site:Eldercare/Backups"
}
```

总管理员在「备份与恢复 → 备份设置」选中目标并点「连接」，后台会补传本机已有的可用快照。修改登记的远端路径后，需要在页面重新连接。验收时点「立即创建快照」，等待状态变成「异地已校验」，据此核对实际账号、存储空间和回读能力。每个机构实例单独设置 `NH_BACKUP_LOCATIONS_FILE`、rclone 配置和业务恢复密钥。

## 原部署不可用时恢复

在另一台主机安装相同版本的应用、SQLCipher 依赖、rclone，重新授权云端目录。取出独立保管的恢复密钥或用 `unwrap-key` 解锁离线恢复材料。以下两条网盘命令可在原工作库丢失时运行。用第一条列出的完整对象名替换示例参数。

```bash
python3 manage_backups.py list-cloud 115
python3 manage_backups.py download 115 '完整对象名.akbak' /private/recovery/received.akbak
python3 manage_storage.py --db /private/recovery/checked.sqlite3 restore /private/recovery/received.akbak --recovery-key-file /private/keys/institution.key
python3 manage_storage.py --db /private/recovery/checked.sqlite3 verify
```

恢复目标必须是新路径。系统会核验文件的认证信息、加密数据库页面和结构。运维人员再核对院区、员工账号和长辈档案数量，抽查医疗原图，随后才将应用指向新工作库。用户需要重新登录。每家机构用独立的恢复密钥，业务恢复材料、平台运维凭据和网盘授权须分别保管。获准的运维人员持有密文和有效密钥后，可离线恢复资料。[密钥封装、保管和灾备](storage.md)
