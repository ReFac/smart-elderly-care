# 医养管理平台机构版商用验收清单

适用于约 200 床机构的私有化交付。功能范围、现有实现证据和数据边界见[商用设计](commercial-design.md)。代码核对基线为 `49f0be2`。下列场景是待执行的联合验收，容量和恢复目标为拟议值，院方与交付方在测试前签认。

## 验收规则

| 类别 | 通过条件 |
| --- | --- |
| 必验 | 使用交付构建和经批准的配置复现预期结果。关键失败路径需核对数据库凭证、审批、审计、告警回执或恢复点。 |
| 联调 | 首发签约范围内的设备、渠道和第三方按实际型号、版本、账号、域名及网络测试。通用接口契约与模拟结果可供预验收，现场配置的签收须附实际回执。 |
| 选配 | SaaS、AI、非首发硬件型号和外部渠道独立签约、开关和验收。关闭后复跑受影响的基础业务和应急路径。 |

每项登记为「通过」「未通过」「待执行」或「双方签认不适用」。已开通功能及必验的隔离、审计、护理安全和恢复条件须通过才能生产签收。用含两院区、同名员工、同号房间、在住和归档长辈、重复事件及无权限账号的虚构数据跑回归。现场联调使用独立测试配置和双方授权的最少数据。

## 试点优先的必验项目

| 编号 | 验收场景和预期结果 |
| --- | --- |
| B01 档案与留存 | 建立含病史、过敏、用药、饮食、联系人和签署协议的档案，走完试住、入住、转区、退住和协议期满。模拟在协议期满后 365 天及法定期限内运行清理，适用档案、协议与原件仍可授权查阅、打印及从副本恢复。检查 AI 草稿、日常列表和授权归档查阅三条路径。迁移前后核对记录数、签署记录及附件摘要，缺失资料进入院方签认的缺口清册。 |
| B02 评估与批量 | 录入能力、压疮及跌倒风险评估，复核后冻结版本。修正一项并升版量表，旧评分、原始答案、签认、原件和曾引用它的计划仍可查。导入包含无效值、重复记录、附件缺失及跨院区数据的文件，预检逐行说明，重复提交只产生一套获准变更，打印或导出能复核源版本。 |
| B03 房间与床位 | 设置房间类型，检查空、在住、外出、临时外出、隔离、维修状态；外出归来可恢复原占用。两位员工同时将不同长辈转入同一床位，只有一项生效。失败不会释放原床或重发账单；床位台账显示原床、新床和时间。批量调整预览隔离、占用与越权冲突。 |
| B04 人员与交接 | 为护理、护士、医生、行政和后勤配置岗位、两院区及相同姓名。排班、考勤和交接按账号 ID 归属，本班接班人能核对并签收，其他同名人不能代签。验证调岗、离职、缺岗替班和跨班补签。总部汇总与分院报表分别按权限核对。 |
| B05 工单闭环 | 手动、告警、家属申请与定时计划都能生成有来源的工单，至少覆盖照护、维修、保洁、送药。按待接单、处理中、待复核、完成或驳回走通。同一单并发领取仅一个成功。配置要求独立复核时执行人不能自审，退回重提不覆盖签认历史。逐步核对登录身份、时间、签认和来源编号。 |
| B06 周期任务 | 建立每两小时、每日早晚及特定星期三种计划，跨午夜、停机重启、暂停恢复和转区下按有效规则派发。到点提醒与未执行升级可见。重复调度不重复派发；补派保留原应执行时间、超时和补做凭证。 |
| S01 呼叫闭环 | 用床头及卫生间测试设备触发普通和紧急呼叫，核对原始设备、地点、绑定床位、发生及接收时间。两名值班人员并发接单时记录唯一首响。提交响应、到场、处置和复核，确认各有时间和人，清楚区分已读、送达与响应。 |
| S02 呼叫升级与故障 | 使用测试时限触发护工、组长、院长逐级升级；模拟缺岗、发送失败、回执丢失和重启。核对备用人、备用通道和告警时钟能恢复。响应后停止接单升级，处置仍可超时。现场验证主服务和外网中断时本地呼叫继续。 |
| R01 数据隔离 | 两院区复用房号和姓名。用护理、临床、财务、Owner、运维和家属账号尝试页面、直接请求、助手、搜索、后台任务及已签发的下载入口，逐项核对获准范围及禁止项。调岗、撤权、家属解绑和恢复快照后须按当前有效权限重新核对。 |
| R02 审计与审批 | 授权和越权各执行一次读病历、导出、下载、更正、归档处置和授权审批。核对身份、可信 IP、机构、对象、范围、版本、理由、时间、结果与审批。应用与日常运维账号无法修改日志；在测试副本上删改段落或校验点，独立核验发现差异并可定位。 |

## 生产前的业务与联调项目

| 编号 | 验收场景和预期结果 |
| --- | --- |
| C01 护理记录 | 录入血压、血氧、体温、血糖及皮肤、进食、排泄与情绪，核对值、单位、来源、发生时间、工单和记录时床位。员工审批更正后原始值和理由仍可查。语音开通时，转写产生草稿并由员工校对保存。 |
| C02 药品追溯 | 用两批不同效期药品及一项高危药做入库、领用、发药、退回和盘点。双人模式下同一账号不得复签。错床、错人、重复发药、过期或召回批次走拒绝或人工处置。已发凭证可查实际长辈、班次、医嘱版本、批号、发药人、复核人和时间。从任一批次可查库存、领用和全部去向。 |
| C03 膳食 | 按星期排三餐，临时改单日。登记低糖、流质、素食、过敏和代餐，核对订餐、实际菜品、未进食及统计口径。餐次确认默认包含适用长辈，支持逐人取消或备注，已确认版本的更正可查。 |
| C04 账务与押金 | 以 31 日入住和人工调整日建立两套账期，覆盖短月和闰年。同一账期并发调度只出一份正式账单。核对床位、护理、餐费、耗材和增值服务，模拟预缴、押金冲抵、部分付款、欠费催缴、手续费、退住退款与原凭证。应收、实收、净入账、余额与舍入均可逐笔对账。 |
| S03 不良事件 | 分别登记跌倒、呛咳、压疮、走失和突发不适，核对原始告警、实际位置、报告、原因、整改责任人、期限和复核人。整改未完成时阻止普通归档，历史更正与打印件可追溯。 |
| S04 告警中心 | 送入雷达、呼叫机、烟感、水浸、任务超时、药品效期及欠费事件，核对分级、接收岗位、已读与响应。分别验证签约的企微、飞书、短信、APP 通道的送达和失败回执。未授权屏蔽申请被拒；允许静默的类别按范围及到期恢复。紧急保护类型的接收、本地告警和操作记录不中断。 |
| I01 协议及设备 | 按签约选型验证床头/卫生间呼叫、毫米波、门磁、烟感、水浸、工牌和体征的型号或仿真契约。对交付启用的 MQTT、HTTP、Modbus 使用真实设备与固件。重放同 ID、同 ID 不同内容、断线、断电、乱序及滞后事件。业务回执对应持久化记录，重复传输只形成一条业务事件，冲突进入待核队列。 |
| I02 设备面板与绑定 | 验证心跳、低电、离线、批量绑定、解绑、故障和维修。换床后重放旧事件，仍按发生时绑定归属；床位无法判定的紧急事件进入当班人工处理。替换同类供应商适配器后复跑同一事件契约及业务闭环。 |
| R03 备份及权限 | 分别核对业务、原件、独立审计的加密副本与异地回读，尝试错误密钥、损坏文件和越权恢复。恢复前有授权和保护点，恢复后核对原件摘要、历史审计、权限、接单、账单、紧急事件与投递水位。 |
| R04 隐私与产品边界 | 检查脱敏、水印、敏感查看审批时限、撤权、水印归属及具体处理事项的告知与授权证据。普通用户、家属、集成账号、Agent、后台任务和直达 API 均不能进入已关闭的纯政务模块。历史资料留在受控保管流程。 |
| X01 家属端 | 用机构小程序的验收环境和真机验证授权、通知、探视改约、留言、账单及获准紧急提醒。家庭 A 无法从直接链接、旧授权或搜索看到家庭 B 的信息。撤销绑定后旧链接也无法查看，消息记录不包含非必要个人信息。 |
| X02 打印与导出 | 用同一数据范围检验护理、交班、不良事件、床位和财务对账的 XLSX 与 PDF。核对授权范围、页眉、日期、单位、合计、水印与源编号。将外部输入的公式样式文本导出，打开表格时按普通文本显示。 |
| X03 对外 API | 验证版本化 OpenAPI 契约、院区范围、分页、最少字段、速率限制、重复请求和 Webhook 回执。对已签约的 HIS 或体检机构实测身份匹配、单位、附件、重复推送与双方对账。既有业务在第三方故障时继续运行。 |
| X04 支付和票据 | 对签约的微信、支付宝或其他渠道验证真实商户的受控测试交易、金额核对、重复回调、部分付款、退款和对账。核对票据开具、红冲或失败后的跟进。关闭外部渠道时仍可用有权限的线下凭证登记。 |

## 交付、容量、恢复与故障演练

| 编号 | 验收场景和预期结果 |
| --- | --- |
| D01 私有化与组织 | 在清洁环境安装，交接 TLS、服务账号、业务与备份密钥的托管责任。建立总部和两分院，验证独立运行权限、加密原件、日常运维与统一汇总。 |
| D02 可配置业务 | 用界面设置量表、周期任务、签认复核、告警分类与升级规则，并预览、生效和回退。旧证据保留生效时配置。尝试通过配置跳过安全核对或关闭紧急接收，服务端拒绝并留痕。 |
| D03 灰度与升级 | 验证试点及稳定通道、签名检查、自动安装设置和升级前可恢复快照。模拟磁盘不足、无效签名及迁移中断，检查旧版本恢复、版本兼容与写入交接。确认升级后的协议、队列、权限、账务和告警均可核对。 |
| D04 日志与监控 | 从同一请求或事件找到系统日志、业务审计、设备日志及投递回执。触发资源异常、队列堆积、存储接近上限、设备离线与备份超龄，运维面板能表现存活与可用状态并通知值班人。 |
| D05 断网兜底 | 先断外网保留院内局域网，完成护理、发药签认、床位和本地呼叫；再让受管护理终端断开局域网，在加密暂存内录入允许的护理草稿。重连重复提交仅一次入账。终端重启、账号撤权、床位转移和受理冲突有明确回执以及人工补录途径。 |
| D06 空机恢复与交接 | 以模拟主机故障起算，从验证过的异地副本在清洁主机恢复，以签署的业务、原件、审计与紧急事件核对结果停止计时。交接部署配置、型号与协议表、角色矩阵、应急卡、五类报表样张、管理员演练和故障响应联系人。 |

### 容量、恢复与故障演练

| 指标 | 拟议验收目标与测量方法 |
| --- | --- |
| 数据规模 | 200 张床、180 位在住长辈、2 个院区、120 名员工及 1,600 个客户账号，其中至少 500 个入住或试住关联账号，其余为仅注册账号。按实际方案模拟 250 台设备、30 个并发员工和 50 个并发家属会话。记录主机、数据库、存储、网络和服务配置。 |
| 正常吞吐 | 按分院查询、工单提交、护理和发药记录、支付查询和报表构成混合负载，至少持续一个完整业务日并覆盖换班及集中出账。院内主要读接口 p95 ≤ 500 ms，主要写操作 p95 ≤ 1 s，常规业务非预期错误率 ≤ 1%。各主要测量类别至少 100 个样本，外部 AI 和大型导出分别测量。 |
| 事件尖峰 | 按 50 事件/秒持续 60 秒验证告警、内部队列和设备回执。拟议目标为紧急事件业务入库回执 p95 ≤ 1 s，入库后站内显示 p95 ≤ 3 s。分别记录外部通道配送时延，验证超限请求明确反馈、常规状态持续可查询、经持久化确认的告警均可重放。 |
| 恢复目标 | 业务 RPO ≤ 12 小时，从故障时点至最新成功验证的异地恢复点计量。RTO 拟议 ≤ 4 小时，从启动恢复到核心工作流与校验通过计量。已回执紧急事件同时用独立网关持久队列或另一故障域做恢复核对。成功入库而未送达的事件进入待投递。 |
| 稳定性 | 报告 CPU、RSS、磁盘与 WAL、接口百分位、失败率、最老任务、设备时延和异地验证年龄。验证断网、单渠道失效、进程重启、重复和乱序、低磁盘、快照恢复及恢复后的账务差额。过载时护理和告警路径按院方签认的优先级降级。 |

已存基线为 2 GiB、2 vCPU Debian/KVM 环境，498 项后端测试通过。32 路模拟上传得到 2 次成功、30 次明确 503，另有 16 次健康检查通过，服务进程峰值 RSS 约 68 MiB。该环境用于验证测试基线和过载保护。200 床混合负载、真实设备与恢复指标待单独实测。

| 编号 | 场景与通过条件 |
| --- | --- |
| A01 语音结构化 | 用正常口述、改口、多人同名、含糊房号和模型超时验证原转写、结构化草稿、确认和放弃。确认前无正式写入，权限校验仍由业务执行。 |
| A02 交班纪要 | 用已授权录音生成按事项、风险、跟进人分组的草案。可定位源片段，缺失信息提示人工补充。签收后可查生成、编辑、确认证据。 |
| A03 声学风险线索 | 在获准样本和现场噪声下统计漏报、误报、时延及不可用比例。声学结果可追至时间窗与配置，临床结论和告警处置仍需相应人员核实。 |
| A04 Agent 工单 | 使用合成告警、超时和重复送达验证业务自动建单、Agent 归纳、提醒、每日简报和确认。关闭模型后复跑调度、告警和手工闭环。 |
| A05 MCP 与 Hook | 按机构、岗位及目标签发工具权限。验证过期授权、越权目标、过量工具调用和重复回调。业务写入使用稳定幂等键，回执能追溯到操作身份、确认与原工具记录。 |
| A06 知识库 | 使用两院区不同版本规程、已失效文档与无权文档。答案呈现已授权有效来源，无法确认时提示人工查询。核对模型调用计量、事件追踪和数据最小化。 |
| D07 SaaS | 启用第二机构并复用业务编号，验证数据库、密钥、备份恢复、对象路径、缓存、队列、用量、报表、日志和运营授权全部隔离。 |

## 发布签认

1. **迁移准备。** 暂停影响法定档案的旧清理，双方确认保管表、资料盘点、缺口单、岗位矩阵及回退窗口。
2. **小范围试点。** 先在一院区或授权房区试运行，签认 B、R01/R02 和实际启用的呼叫闭环，保留原应急流程。按反馈和故障记录逐步扩大。
3. **机构生产交付。** 签认所有必验、启用的联调项目、性能记录和灾备演练。法定档案缺失、给药核对失效、紧急告警漏入库、跨范围访问、审计可被改写、无法恢复或账实不符均为上线阻断项。
4. **增值发布。** 按签约范围启用 AI 或 SaaS。院方指定护理、财务、设备和 IT 责任人分别签认其业务证据，交付方确认版本与回退材料。

每条记录包含验收编号、构建或镜像摘要、配置版本、院区及设备、执行人和日期、预期及实测、脱敏证据、状态、缺陷编号与复测结果。签收件由双方保存。
