# 长者档案与文书存档

所有入住、转床和医疗文书均关联预先建立的长者档案号。转床后，历史文书、亲属账号及原件继续关联同一人。总管理员在「账号与权限」中创建家属账号并绑定一位长者。家属登录后，在「家属服务 → 我的亲属资料」中填写本人资料。

## 登记字段

| 部分 | 必填 | 可补录字段 |
| --- | --- | --- |
| 基础身份 | 档案号、姓名 | 出生日期、出生地、籍贯、登记年龄、现住址、原职业、文化程度、常用语言或方言、婚姻情况。出生日期优先用于计算周岁。 |
| 家庭与经济 | 关联长者 | 兄弟姐妹、子女及照护分工、原居住与照料安排、费用来源（可多选）、养老金月收入、经济补充说明。子女可逐人登记经济支持及月均金额。 |
| 家庭成员与联系人 | 每人填写姓名及成员类别。承担联系用途时还需填写电话 | 可登记一位配偶、逐一添加全部子女及其他联系人，每人保存具体关系、联系地址、照护分工和最近人工拨通日期。同一人可兼任推荐、常用及紧急联系人。 |
| 家属自助 | 本人姓名、关系、电话 | 居民身份证号、地址、微信、邮箱和紧急联系说明。身份证号核对长度、出生日期格式与校验位，身份核验另由机构办理。 |
| 医疗记录 | 记录就诊或文书日期，核对原文事实。 | 可附 JPEG、PNG 或 PDF 原件。手工病史补录可只提交文字，既往用药和本次处方分别填写。 |

员工按岗位权限获取字段。基本资料维护需要 `intake`，查阅需要 `residents` 或 `intake`。家庭与经济资料另需 `relatives`。亲属本人和总管理员可查阅完整身份证号，有亲属联络权限的员工看到掩码。普通员工无法代替亲属修改该档案。总管理员代录时，服务端从账号表核对家属身份和绑定关系。

从长者名册和床位打开的简易档案只显示常用资料、健康简介和近期变化。点标题栏的「打开详细档案」，在左侧切换「登记资料」「医疗资料」和「疗养院时间线」。登记资料包括入住、家庭和获授权的收费明细。医疗资料首先显示每次就诊及补充记录，然后列出既往医疗文书。疗养院时间线显示已签认的用餐与集体活动，以及岗位获准查看的护理和入住历史。个人与医疗档案名册直接打开医疗资料，伙食记录链接直接定位到对应的一餐。

## 地区与经济资料

在「编辑登记资料」中，出生地和籍贯按省、市选择，可继续选到区县。本人、家庭联系人及亲属账号的联系地址按省、市、区县联动，再选目录已有的乡镇街道、村居。街巷门牌另填，历史自由文本会在修改前原样展示。已知上级地区但下级目录缺项时，选「目录未收录」并按证件补入地名，系统将其与选中地区一并保存。职业、文化程度、常用语言、婚姻情况和原居住安排使用固定选项。

「收费」列出财务账单和分项凭证，需要财务权限。「费用来源」可同时选择子女、本人、补贴等来源。「长者养老金收入」可按月选择区间或登记精确金额。经济资料沿用亲属资料权限。登记每位子女时可选择支持状态，并为提供支持的子女登记月均区间、精确金额或待核实。养老金和家庭支持信息来自登记人，不会被当作已到账款项。

### 地址目录覆盖与更新

- 内地省、市和县区使用 2023 年统计用区划快照；香港、澳门和台湾采用同一上游项目的独立 `HK-MO-TW.json` 名称表，供省级、地区/城市、区级联动。离线目录含 34 个省级选项。香港、澳门和台湾的补充层级标识为本系统查询键。直辖市会保留可供联动的中间层级，最终显示的地址省略「市辖区」等占位名称。[上游仓库及数据说明](https://github.com/modood/Administrative-divisions-of-China/tree/c49d495b40ac73eb1a66f6eeae5f8fd10696f035)
- 河南收录 2,586 个乡镇、街道或统计功能区及 52,378 个村居或统计单位。平顶山的 2,828 个村居随基础目录加载，河南其他地市的村居按所选城市从院内服务器读取，汝州其中有 21 个乡镇街道、466 个村居选项。可选「河南省 → 平顶山市 → 汝州市 → 洗耳河街道 → 十里村民委员会」，再填写门牌。其他地区的街巷可在详址补录。统计功能区包含在地址选项中，正式行政区数量以政府公布为准。[平顶山市政府区划说明](https://www.pds.gov.cn/contents/16/51168.html)
- 此版本已按汝政〔2024〕22号改为骑岭街道，并将白马村归入该街道。其他年份的更名或撤并可能尚未收录。记录保留所选的稳定内部查询键及当时格式化的地址文本。[汝州市政府通知](https://www.ruzhou.gov.cn/contents/36910/418767.html)
- 区划原始仓库发布许可为 WTFPL v2。部署只需仓库内的静态 `web/assets/address-regions.json` 和同目录下的 `henan-villages/` 区划分片；选址和校验均在机构应用内完成。手机号、地址及选择过程无需发送给地理服务。要更新目录，将固定版本的 `dist/` 下载到本地，执行 `python3 tools/build_address_catalog.py /path/to/dist web/assets/address-regions.json`，复核属地变更后发布。[数据许可](https://github.com/modood/Administrative-divisions-of-China/blob/c49d495b40ac73eb1a66f6eeae5f8fd10696f035/LICENSE)

## 长期护理保险

总管理员在「账号与权限」给经办人分配「长护险参保、评估和待遇经办」，员工进入「机构运营 → 长期护理保险」即可选择自己的授权区域内的长者档案。既有正式待遇文书可直接补录，常规办理顺序为参保、申请、登记正式评估结论、登记待遇核定或未予核定。后续可记录复评和待遇终止。

每次办理保存日期、统筹地区、正式文书或受理编号、经办人和相应阶段专属的资料。核定待遇时需选服务方式、登记起始日，按文书补录截止日；系统据此显示当前有效期。待遇标准、评估等级和服务方式由参保地正式文书确定。模块目前用于机构台账，官方评估、基金申报及实际支付仍由属地经办渠道办理。[国家医保局长期护理保险实施方案](https://www.nhsa.gov.cn/art/2026/3/26/art_53_20040.html) · [评估管理办法](https://www.nhsa.gov.cn/art/2023/12/15/art_104_11715.html)

`ltci.record` 通过标准命令接口提交，写入 `residentId`、`event`、`date`、`region` 和 `reference`，核定待遇时还需 `service` 和 `startsOn`。服务端检查阶段顺序、日期、文书资料、当前角色及分院范围。正式办理记录按顺序追加，进入长者历史和加密备份；会覆盖已存在经办凭证的在线恢复会提示冲突。

## 家庭资料与巡查分享

在「个人与医疗档案 → 打开详细档案 → 家庭成员与联系人」逐人登记，也可从「长者档案」打开详细档案。长者本人的住址填在「编辑登记资料 → 现居住址」，每位成员另有自己的联系地址。原有的子女及照护分工文字与入住联系电话继续保留。更新成员需要同时具有入住管理和亲属资料权限。登记紧急联系人时填写有效电话。工作人员在实际拨通后选择「已人工拨通」并填写日期，更换号码后需重新核实。成员的增删修改在该长者的「最近改动」中留痕，可在权限及版本条件允许时撤销。

1. **登记分享意愿。** 总管理员先绑定家属账号。长者用自己的账号进入「长者服务 → 分享授权」，逐位选择可以接收简报的家属。总管理员或同时具有 `relatives` 与 `family.share` 的员工也可在长者详细档案的「家属简报分享授权」代录。代录时记录当面、电话或书面确认方式和具体经过，系统登记经办人及时间。员工仅可办理获准分院的长者。
2. **家属订阅。** 家属在「家属服务 → 巡查简报」打开自己的每日订阅。新账号默认关闭。登记为紧急联系人、填写亲属档案、开通照护工单或用药查阅均不会开通简报。每位家属单独选择。
3. **查收与签收。** 到达机构设置的推送时刻后，当日已有巡查简报且两方均同意，系统投递到家属的站内收件箱。每个账号对每位长者每天最多收到一份。家属收件沿用订阅时约定的简要范围，提供当日照护计划、完成和待办数量。只有已核实的咳嗽观察达到明显增加的显示条件时才建议联系护理人员。家属的订阅不包含逐日生活简报、个人餐量、健康简介及医疗原文。长者本人可由管理员另行开通「个人生活与健康档案」，阅读本人的生活简报和已确认的健康简介。家属在「家属服务 → 巡查简报」查看最近 60 份可查简报并标为已读。员工原始证据、详细病历、其他家庭资料均留在机构内。当前投递渠道为站内收件箱。
4. **撤回与恢复。** 长者可撤回任一家属的授权，家属也可取消订阅。任一方撤回立即停止查阅和继续投递。重新同意后只展示新一轮授权下送达的简报。停用家属账号后，两方均需重新确认。在线导入机构快照会恢复当时的家庭档案资料，当前分享意愿、订阅和收件凭证以运行库为准。离线灾备到新路径时保留历史凭证，并暂停家属分享和订阅，两方重新确认后才能接收新简报。

## 单次就诊病例

1. 在「健康助理 → 传就诊资料」先选长者，再选已有就诊记录，或在新建时填写就诊日期。每组最多 12 份 JPEG、PNG 或 PDF，单份最多 8 MiB，合计最多 24 MiB。核对归属后点「开始识别并核对」。已归档长者的病例供查阅。
2. 在核对窗口切换原件，检查机构、科室、症状、医生诊断、检查结论、就诊前用药、本次处方、医嘱和复诊安排。核对医院名称时可用简称查目录，也可按原件填写。展开「识别时参考的原文」可查看资料和页码。CT 影像留存原件，检查结论从书面报告中提取。发现姓名或就诊日期冲突时，返回重新分组。
3. 核对后点「确认添加此病例」或「确认补充资料」。在长者详细档案的「医疗资料 → 就诊病例与过往记录」可以查看每次就诊、原始签认和历次补充。补充沿用原就诊日期，独立保存经办人、签认时间和原件。重复整理同一组资料复用已经完成的云端识别和整理结果。
4. 在长者档案点「手动录入病例」，可分别填写既往用药、本次处方、检查和医嘱，也可选择附上 CT、处方或出院小结。

整理和签认要求经办人具有医疗档案查阅、文书写入和临床权限，并在该长者的授权范围内。预览接口为 `POST /api/residents/{residentId}/medical-visits/preview`，签认使用 `dossier.confirmVisit`。已签认病例的原件通过 `GET /api/medical-visits/originals/{id}` 在当前权限下读取，计入机构加密备份。

## 归档行为

1. 在长者详细档案内选择「存档医疗文书」。填写文书实际发生日期与来源，可从照片库选图、使用手机相机拍摄，也可整份上传多页 PDF。每份原件最大 8 MiB。选择 OCR 时，提交前会显示实际页数和预计使用额度。
2. 核对并填写原文事实。可采用经人工核对的转录，也可以手工描述。归档账户即为本次核对人。
3. 提交时一次生成结构化概括，包含文书日期、类型、来源、文字来源、原文事实、待核实事项和核对人。系统保存填写内容和登录身份，形成固定版本。之后打开详情直接读取该版本。
4. 时间线按文书发生日期倒序，同日按入库先后倒序。详情可查存档日、原图或 PDF 各页，也可下载完整的 PDF 原件。数据库保存的原件与上传字节一致。手工录入时，原件、签认概括和审计记录同时归档。选择 DeepSeek OCR 时，先留存原件，再单独核对并签认概括。

护士核实后的跌倒处置进入同一长者的「护理复核与历史摘要」，保留发生时间、房间、复核人和处置说明。

## 接口

| 方法 | 用途 | 权限 |
| --- | --- | --- |
| `POST /api/commands · dossier.profile` | 用 `residentId` 编辑基础登记及获准的家庭字段 | `intake`。涉及家庭经济或家庭成员时同时需要 `relatives` |
| `POST /api/commands · family.consent` | 提交 `residentId`、家属 `accountId` 与布尔 `enabled`。员工代录另需 `method` 与 `evidence` | 长者本人或有权代录者 |
| `POST /api/commands · family.subscribe` | 家属设置绑定长者的站内订阅意愿 | 亲属本人 |
| `POST /api/commands · family.read` | 标记指定 `messageId` 已读，服务端重新核对本人、长者及有效授权 | 收件亲属本人 |
| `POST /api/commands · dossier.relative` | 家属编辑自己的联系方式、证件和关系。业主可代录已绑定账号 | 家属本人、总管理员 |
| `POST /api/commands · dossier.document` | 校验、留存原件及首次概括 | `medical.write` |
| `GET /api/documents/{id}/image` | 按服务端会话授权返回原始 JPEG 或 PNG | `medical` |
| `GET /api/state` | 读取按岗位投影的 `dossierProfiles`、`medicalDocuments`、`relativeProfiles` | 服务端逐集合、字段核对 |

`dossier.profile` 的 `familyContact` 可向当前长者的家庭名册添加成员，携带成员 `id` 可编辑，携带 `id` 及 `remove: true` 可移除。`GET /api/state` 为有权登记者返回 `familyRoundRecipients`，为家属本人返回含订阅意愿、长者授权状态与可查简报的 `familyRoundInbox`。

归档命令传入 `requestId`、`residentId`、`eventDate`、`category`、`source`、`description` 和可选 `pending`。原件内容使用 `imageBase64`，可附 `mime` 与 `filename`。PDF 类型为 `application/pdf`，可先将原始二进制以该类型提交至 `POST /api/residents/{id}/document-pages` 核页。客户端收到数据版本冲突后，先读取最新快照，再决定是否用原请求编号提交。相同输入复用现有文书，相同原件带不同描述时返回校验错误。同一张图在不同长者名下分别留存证据。机构按原图哈希复用转录，每份档案单独核对身份、签署概括并保留回填凭证。

医疗文书表存储 SHA-256、原图和概括版本。读取列表只查询元数据，数据库触发器阻止应用更新或删除已归档行。原件归档的持久性还取决于 SQLite 文件的备份和恢复。

## 出院小结识别与签认

上传原件后选择 DeepSeek OCR，确认发送后等待识别。复核人在原图旁逐行检查姓名、诊断、过敏史和高危提示。有位置框的行可点击定位。复核者可手工纠错、勾选拟回填字段并查看现有值。姓名与当前长者不一致时，仅可保留核对概括。多页 PDF 逐页核对，`reviewedPages` 保留已核对页码。服务端核对归属、权限、页码、页内行号与原值。核对通过后保存复核者、日期、前后值和唯一概括。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `dossier.document`，`method=DeepSeek OCR` | `medical.write` | 保存完整原件、来源与日期 |
| `dossier.ocr` | `medical.write` | 核验分院授权与发送确认，按图像复用转录 |
| `GET /api/documents/{id}/ocr` | `medical` | 按需读取原文行、可用的位置与候选 |
| `dossier.reviewDocument` | `medical.write`、`medical`、`clinical` | 签认概括以及选定的档案字段 |

开通套餐、停用工具、处理中断和语音确认流程见[识别工具说明](media.md)。

## 动态档案摘要

在长者的「个人与医疗档案」选择「核对动态档案摘要」。本地读取当前护理等级、已登记过敏与高危要点，至多两条近期照护复核及两份已签认文书，列出来源编号并显示摘录。尚待核对、识别人名不符的文书不参与取材。点击生成时，DeepSeek 根据护理等级、已复核的照护记录数和文书类别写出核对提示。原文、档案编号及健康字段留在机构内供签认人比对和补写。相同证据集复用一次云端结果，预览及反复阅读均不写入档案。具备 `medical` 和 `clinical` 的人员可修订草稿并签认，生成一次可追溯的当前摘要。签认前若依据发生变动，系统要求重新核对。历史中保留每个版本的来源、核对人、日期及当次正文。

`GET /api/residents/{id}/summary-draft` 返回该长者草稿、依据和指纹。`dossier.signSummary` 在写入时按长者重验依据、岗位和指纹。

## 个体健康照护计划草稿

在 Agent 工作台选择「生成健康照护计划」和一位在住长者，或打开「专项建议台账 → 日常照护」。系统依据该长者最近的有效评估、已确认的生活协助需求以及关联计划，整理服务项目、责任人与复评日，注明待观察项目和当日到期工单。缺少评估、责任人或复评日时请先补齐。Agent 只保存待审草稿。生成、发布、建议台账的采纳操作均不会派工。正式派工在「能力评估 → 照护计划」由有权人员复核。启用房间授权的人员可从房间工作台进入本房协作，选取其中一位长者。草稿使用本地只读工具 `care.planDraft`。

## 体检用药自报

长者本人在「长者服务 → 我的用药自报」填写体检时的用药情况。总管理员可在该长者的本人账号单独勾选「本人填写、查看及更正体检用药自报」。有照护权限的员工可以在「健康体征 → 体检用药自报」按本人口述代录。长者详情和医疗档案均可查看自报原文、所选药名、日期、用法及历次更正。临床给药仍以经复核的医嘱为依据。

填写两个字后，界面会显示前缀、包含或相近写法的候选。例如输入「阿莫西淋」，可展开目录原页，对照包装确认「阿莫西林」，也可将原话标为待核对。候选来自国家医保局 2025 年药品目录中可以明确解析的单行药名，覆盖范围以这份目录为限。目录查询只用于核对名称。商品名、复杂组合条目及自费药可能无匹配结果。[国家医保局目录及发布说明](https://www.nhsa.gov.cn/art/2025/12/7/art_104_18970.html)

目录服务需要 `pdftotext`（Poppler）和访问 `www.nhsa.gov.cn` 的出站 HTTPS。每个服务进程首次查询时下载公开文件，校验固定版本 SHA-256 与已知药名，然后缓存一天。目录联想在院内运行。刷新失败会标明使用上次读取的目录，首次失败则允许仅保存原文。更新目录版本时，应同时核验文件链接、摘要、版式及原文页码。

需要实时查某个商品名或目录外名称时，点击「联网查此药名」，也可勾选「联网自动补全」。开关初次默认关闭，当前账号在同一浏览器标签页只需开启一次。开启后，输入至少两个字并停顿约半秒，界面会同时保留医保目录候选和实时来源供核对。系统仅将当前药名送往 Wikidata 官方检索 API，核验条目的药品 ATC 代码，再显示候选和出处。查询前会在院内排除已登记人员姓名、房号和联系方式。界面也提供按本次词语打开国内药学数据中心的链接。来源不可用时仍可保留原话待核。实时检索需要访问 `www.wikidata.org`。[Wikidata 数据访问说明](https://www.wikidata.org/wiki/Wikidata:Data_access) · [药学数据中心](https://pharm.ncmi.cn/)

`GET /api/residents/{id}/reported-medications` 读取该长者的自报及更正历史。`GET /api/residents/{id}/drug-names?q=…` 返回限定数量的目录候选和来源页，显式加 `online=1` 才查询外部药名。确认提交使用 `portal.reportMedication`（本人）或 `care.reportMedication`（照护人员）。更正使用记录编号和上一版本号，服务端逐次保留原文和经办人。亲属的医嘱查阅授权独立于本人的填报授权。
