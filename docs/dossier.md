# 长者档案与文书存档

「个人与医疗档案」复用入住时生成的长者档案号。转床后，历史文书、亲属账号及原件继续关联同一人。总管理员在「账号与权限」中创建家属账号并绑定一位长者。家属登录后，在「家属服务 → 我的亲属资料」中填写本人资料。

## 登记字段

| 部分 | 必填 | 可补录字段 |
| --- | --- | --- |
| 基础身份 | 档案号、姓名 | 出生日期、出生地、籍贯、登记年龄、现住址、原职业、文化程度、常用语言或方言、婚姻情况。出生日期优先用于计算周岁。 |
| 家庭与经济 | 关联长者 | 兄弟姐妹、子女及照护分工、原居住与照料安排、收入与费用来源、经济补充说明。 |
| 家庭成员与联系人 | 每人填写姓名及成员类别。承担联系用途时还需填写电话 | 可登记一位配偶、逐一添加全部子女及其他联系人，每人保存具体关系、联系地址、照护分工和最近人工拨通日期。同一人可兼任推荐、常用及紧急联系人。 |
| 家属自助 | 本人姓名、关系、电话 | 居民身份证号、地址、微信、邮箱和紧急联系说明。身份证号核对长度、出生日期格式与校验位，身份核验另由机构办理。 |
| 医疗记录 | 文书日期、类型、来源。签认时需核对原文事实。 | 待核实事项。CT、其他影像、诊断记录、检验报告、出院小结及其他医疗文书需附 JPEG 或 PNG 原件。手工病史补录可只提交文字。 |

员工按岗位权限获取字段。基本资料维护需要 `intake`，查阅需要 `residents` 或 `intake`。家庭与经济资料另需 `relatives`。亲属本人和总管理员可查阅完整身份证号，有亲属联络权限的员工看到掩码。普通员工无法代替亲属修改该档案。总管理员代录时，服务端从账号表核对家属身份和绑定关系。

## 家庭资料与巡查分享

在「个人与医疗档案 → 打开详细档案 → 家庭成员与联系人」逐人登记，也可从「长者档案」打开详细档案。长者本人的住址填在「编辑登记资料 → 现居住址」，每位成员另有自己的联系地址。原有的子女及照护分工文字与入住联系电话继续保留。更新成员需要同时具有入住管理和亲属资料权限。登记紧急联系人时填写有效电话。工作人员在实际拨通后选择「已人工拨通」并填写日期，更换号码后需重新核实。成员的增删修改在该长者的「最近改动」中留痕，可在权限及版本条件允许时撤销。

1. **登记分享意愿。** 总管理员先绑定家属账号。长者用自己的账号进入「长者服务 → 分享授权」，逐位选择可以接收简报的家属。总管理员或同时具有 `relatives` 与 `family.share` 的员工也可在长者详细档案的「家属简报分享授权」代录。代录时记录当面、电话或书面确认方式和具体经过，系统登记经办人及时间。员工仅可办理获准分院的长者。
2. **家属订阅。** 家属在「家属服务 → 巡查简报」打开自己的每日订阅。新账号默认关闭。登记为紧急联系人、填写亲属档案、开通照护工单或用药查阅均不会开通简报。每位家属单独选择。
3. **查收与签收。** 到达机构设置的推送时刻后，当日已有巡查简报且两方均同意，系统投递到家属的站内收件箱。每个账号对每位长者每天最多收到一份。简报显示当日计划、已完成、待完成和逾时工单数。若已核实的可比时段咳嗽频率高于本人近期水平，简报提示联系护理人员核实。家属在「家属服务 → 巡查简报」查看最近 60 份可查简报并标为已读。员工原始证据、详细病历、其他家庭资料均留在机构内。当前投递渠道为站内收件箱。
4. **撤回与恢复。** 长者可撤回任一家属的授权，家属也可取消订阅。任一方撤回立即停止查阅和继续投递。重新同意后只展示新一轮授权下送达的简报。停用家属账号后，两方均需重新确认。在线导入机构快照会恢复当时的家庭档案资料，当前分享意愿、订阅和收件凭证以运行库为准。离线灾备到新路径时保留历史凭证，并暂停家属分享和订阅，两方重新确认后才能接收新简报。

## 归档行为

1. 在长者详细档案内选择「存档医疗文书」。填写文书实际发生日期与来源，可从照片库选图或使用手机相机拍摄。单张原件最大 8 MiB，多页资料可逐页归档。
2. 核对并填写原文事实。可采用经人工核对的转录，也可以手工描述。归档账户即为本次核对人。
3. 提交时一次生成结构化概括，包含文书日期、类型、来源、文字来源、原文事实、待核实事项和核对人。系统保存填写内容和登录身份，形成固定版本。之后打开详情直接读取该版本。
4. 时间线按文书发生日期倒序，同日按入库先后倒序。详情可查存档日和照片原尺寸。数据库保存的原件与上传字节一致。手工录入时，原件、签认概括和审计记录同时归档。选择 DeepSeek OCR 时，先留存原件，再单独核对并签认概括。

护士核实后的跌倒处置进入同一长者的「护理复核与历史摘要」，保留发生时间、房间、复核人和处置说明。

## 接口

| 方法 | 用途 | 权限 |
| --- | --- | --- |
| `POST /api/commands · dossier.profile` | 用 `residentId` 编辑基础登记及获准的家庭字段 | `intake`。涉及家庭经济或家庭成员时同时需要 `relatives` |
| `POST /api/commands · family.consent` | 提交 `residentId`、家属 `accountId` 与布尔 `enabled`。员工代录另需 `method` 与 `evidence` | 长者本人或有权代录者 |
| `POST /api/commands · family.subscribe` | 家属设置绑定长者的站内订阅意愿 | 亲属本人 |
| `POST /api/commands · family.read` | 标记指定 `messageId` 已读，服务端重新核对本人、长者及有效授权 | 收件亲属本人 |
| `POST /api/commands · dossier.relative` | 家属编辑自己的联系方式、证件和关系。业主可代录已绑定账号 | 家属本人、总管理员 |
| `POST /api/commands · dossier.document` | 校验、留存原件及首次概括 | `medical.write` |
| `GET /api/documents/{id}/image` | 按服务端会话授权返回原始 JPEG 或 PNG | `medical` |
| `GET /api/state` | 读取按岗位投影的 `dossierProfiles`、`medicalDocuments`、`relativeProfiles` | 服务端逐集合、字段核对 |

`dossier.profile` 的 `familyContact` 可向当前长者的家庭名册添加成员，携带成员 `id` 可编辑，携带 `id` 及 `remove: true` 可移除。`GET /api/state` 为有权登记者返回 `familyRoundRecipients`，为家属本人返回含订阅意愿、长者授权状态与可查简报的 `familyRoundInbox`。

归档命令传入 `requestId`、`residentId`、`eventDate`、`category`、`source`、`description` 和可选 `pending`。有照片时传 `imageBase64`，可附 `mime` 与 `filename`。客户端收到数据版本冲突后，先读取最新快照，再决定是否用原请求编号提交。相同输入复用现有文书，相同原件带不同描述时返回校验错误。同一张图在不同长者名下分别留存证据。机构按原图哈希复用转录，每份档案单独核对身份、签署概括并保留回填凭证。

医疗文书表存储 SHA-256、原图和概括版本。读取列表只查询元数据，数据库触发器阻止应用更新或删除已归档行。原件归档的持久性还取决于 SQLite 文件的备份和恢复。

## 出院小结识别与签认

上传原件后选择 DeepSeek OCR，确认发送后等待识别。复核人在原图旁逐行检查姓名、诊断、过敏史和高危提示。有位置框的行可点击定位。复核者可手工纠错、勾选拟回填字段并查看现有值。姓名与当前长者不一致时，仅可保留核对概括。服务端核对归属、权限、行号与原值。核对通过后保存复核者、日期、前后值和唯一概括。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `dossier.document`，`method=DeepSeek OCR` | `medical.write` | 保存原图、来源与日期 |
| `dossier.ocr` | `medical.write` | 核验分院授权与发送确认，按图像复用转录 |
| `GET /api/documents/{id}/ocr` | `medical` | 按需读取原文行、可用的位置与候选 |
| `dossier.reviewDocument` | `medical.write`、`medical`、`clinical` | 签认概括以及选定的档案字段 |

开通套餐、停用工具、处理中断和语音确认流程见[识别工具说明](media.md)。

## 动态档案摘要

在长者的「个人与医疗档案」选择「核对动态档案摘要」。本地读取当前护理等级、已登记过敏与高危要点，至多两条近期照护复核及两份已签认文书，列出来源编号并显示摘录。尚待核对、识别人名不符的文书不参与取材。预览及反复阅读均不写入档案。具备 `medical` 和 `clinical` 的人员可修订草稿并签认，生成一次可追溯的当前摘要。签认前若依据发生变动，系统要求重新核对。历史中保留每个版本的来源、核对人、日期及当次正文。

`GET /api/residents/{id}/summary-draft` 返回该长者草稿、依据和指纹。`dossier.signSummary` 在写入时按长者重验依据、岗位和指纹。

## 个体健康照护计划草稿

在 Agent 工作台选择「生成健康照护计划」和一位在住长者，或打开「专项建议台账 → 日常照护」。系统依据该长者最近的有效评估、已确认的生活协助需求以及关联计划，整理服务项目、责任人与复评日，注明待观察项目和当日到期工单。缺少评估、责任人或复评日时请先补齐。Agent 只保存待审草稿。生成、发布、建议台账的采纳操作均不会派工。正式派工在「能力评估 → 照护计划」由有权人员复核。启用房间授权的人员可从房间工作台进入本房协作，选取其中一位长者。草稿使用本地只读工具 `care.planDraft`。
