# 渠道收款、经营月报与民政回执

## 桌面验收

1. 财务人员在「财务结算 → 渠道对账」选账单、渠道和金额，生成商户订单。机构配置收银凭证后，点击订单的「显示收款码」，让付款人使用相应应用扫描并核对金额与商户。后台验证到账通知后，桌面显示到账并收起二维码。机构已有独立收银系统时，也可把本平台订单号作为收银端的 `out_trade_no`。
2. 已有线下商户对账单时，点击「登记渠道对账凭证」，填写原始商户订单号、渠道交易流水号、实际到账日期和对账依据。凭证明确标为财务人工核对。在线回调凭证标为渠道签名通知。同一渠道订单号或流水号只能关联一笔到账。完全相同的重复通知不会再次入账。
3. 核销时若其他收款已抵扣部分余额，剩余实收计入这位长者的预交账户，并沿用已有的欠款冲抵顺序。月度入款分别计算实收核销和预交到账，预交冲抵单独列示。登记已发生的支出时须填写凭证编号、分类、金额、收款对象及用途。
4. 「欠费提醒」显示服务期已结束且余额大于零的账单。登记实际电话、当面或机构消息的跟进结果后，保留当时的欠款金额。催缴登记不向外发送消息。
5. 「统计报送 → 经营月报」按已授权的业务域展示指标。选择当前月时，环比取上月相同天数，最多到上月月末。选择历史月时，以两个完整自然月对比。经营诊断展示到账笔数、最大支出类别、待执行工单和物资领用品种。点击「对比明细」可核对两期单据。
6. 「统计报送 → 民政报送」生成草稿并核对问题，下载加密的 `.akdoc`。授权的总部报送人员在本机构「民政报送 → 打开加密文件」调阅。接入当地民政系统时按受控接口与报送渠道送出。登记实际接收方与送出凭证后固化该版快照。接收方退回时登记回执号及原因，补正源数据后生成下一版。已送各版可单独导出，已受理月份保留签收版本。当地政务平台的字段、域名、证书和正式接收回执由接收机构提供。

民政月报的照护运营汇总面向本期在院服务对象。计划工单按计划日期归集，有效完成量按完成日期归集，实际服务人数按已完成工单中的长者去重。旧工单缺少完成日期时按计划日归集。补正前各次已送快照均保留当版汇总。

## 账单分段规则

- 日费随床位和已审核通过的照护等级生效。同日多次变动，以当天最后一次已生效状态计价。入住和退住当天均计费，退住日沿用最后占用的床位。在住长者生成当月账单时，以当时已知的安排估算至月末。
- 床位费按入住日数收取。护理费按服务日期逐日计收，请假日保留床位并免护理费。账单明细显示每段日期、床位、等级、两项单价、服务日与请假日。账单生成时冻结该次核算的价格及分段。
- 财务可按合同另填床位、护理日费或约定请假天数。若整月护理单价不同且人工请假天数与请假台账有出入，须先补齐请假日期，或按合同提供统一护理单价。新入住、转床与等级审核记录保存当时的计费条件。旧记录缺少当时单价或等级时，使用可查的床位定价和档案护理等级回算。

## 商户通知端口

支付收银侧须把商户通知指向机构公开的 HTTPS 服务。机构工作台按 README 配置受信域名。签名使用独立的商户配置，所配公钥、商户号、应用号必须属于本机构签约的对应支付渠道。回调验签使用服务端加密依赖 `cryptography`。微信 APIv3 密钥文件由部署方保管。

| 渠道 | 接口与成功应答 | 服务端配置 |
| --- | --- | --- |
| 微信支付普通商户 APIv3 | `POST /api/payments/notify/wechat`，JSON；成功返回 200。校验微信支付公钥 ID、时间和原始报文 RSA 签名，再用 AES-256-GCM 解密成功交易。 | `NH_WXPAY_PUBLIC_KEY_FILE` 指向微信支付 RSA 公钥 PEM，`NH_WXPAY_PUBLIC_KEY_ID` 对应公钥 ID，`NH_WXPAY_V3_KEY_FILE` 指向 APIv3 密钥文件，另配 `NH_WXPAY_APP_ID` 和 `NH_WXPAY_MERCHANT_ID`。 |
| 支付宝普通直连、UTF-8、RSA2 公钥模式 | `POST /api/payments/notify/alipay`，表单编码；成功返回文本 `success`。验签后核对 `app_id`、`seller_id`、付款状态、币种、原始订单和金额。 | `NH_ALIPAY_PUBLIC_KEY_FILE` 指向支付宝平台公钥 PEM，另配 `NH_ALIPAY_APP_ID` 和 `NH_ALIPAY_SELLER_ID`。 |

微信通知签名验证原始正文及平台请求头。支付宝按官方 SDK 对业务参数排序，由 RSA2 验签。未登记的订单、签名不正确、金额或商户不匹配均返回非成功状态，不产生收款流水。测试在临时库使用独立生成的密钥和签名通知。商户联调须使用机构授权的密钥和收银系统。[微信支付回调文档](https://pay.wechatpay.cn/doc/v3/merchant/4012791836) · [支付宝官方 SDK 验签逻辑](https://github.com/alipay/alipay-sdk-java-all/blob/master/v2/src/main/java/com/alipay/api/internal/util/AlipaySignature.java)

## 可选商户收款码

在服务端的运行环境安装 `python3 -m pip install -r requirements-payments.txt`。设置 `NH_PAYMENT_PUBLIC_ORIGIN` 为由机构提供 HTTPS 反向代理的根域名，例如 `https://care.example.org`。按上表配置到账通知的商户身份及验签材料。

| 收银渠道 | 补充配置 | 申请与核对 |
| --- | --- | --- |
| 微信 Native | `NH_WXPAY_PRIVATE_KEY_FILE` 指向商户 API 证书的 RSA 私钥 PEM，`NH_WXPAY_CERT_SERIAL` 为对应商户证书序列号。 | 财务工作台向微信 Native 接口签名下单并校验平台应答签名，在本机将 `code_url` 编为二维码。 |
| 支付宝当面付 | `NH_ALIPAY_PRIVATE_KEY_FILE` 指向应用签名私钥 PEM，配合平台侧已登记的应用公钥。 | 工作台调用 `alipay.trade.precreate`，验证应答正文的 RSA2 签名、结果码和商户订单号，在本机将 `qr_code` 编为二维码。 |

可用渠道由服务端根据收银组件、商户配置和密钥文件的可读性决定。财务操作需要登录且具备财务权限。首次取码和到账分别记录审计。重复打开有效二维码沿用同一商户订单。同一订单并发申请只发出一次。付款页面每四秒检查本地实收状态。订单金额、商户、费用描述及回调地址均由服务端生成，无需向渠道提供长者姓名或病历。机构上线时须开通对应收银产品，并使用机构自己的商户账号核对公网回调和实收对账。[微信 Native 下单接口](https://pay.wechatpay.cn/doc/v3/merchant/4012791877) · [支付宝官方预下单请求](https://github.com/alipay/alipay-sdk-python-all/blob/master/alipay/aop/api/request/AlipayTradePrecreateRequest.py)


统计报送账号可用 `GET /api/reports/{reportId}/versions/{version}` 读取已登记送出的固定版本。响应以 `ankang.civil.monthly.v1` 标出院内数据契约，附机构编号、接收单位、送出凭证、日期和原版数据集。数据集记录入住、退住、期末在住和月内照护运营数量。当地平台的字段映射、签章、传输和回执认证由接收方协议决定。
