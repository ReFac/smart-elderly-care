# 渠道收款、经营月报与民政回执

## 桌面验收

1. 财务人员在「财务结算 → 渠道对账」选账单、渠道和金额，生成商户订单。机构配置收银凭证后，点击订单的「显示收款码」，让付款人使用相应应用扫描并核对金额与商户。后台验证到账通知后，桌面显示到账并收起二维码。机构已有独立收银系统时，也可把本平台订单号作为收银端的 `out_trade_no`。
2. 已有线下商户对账单时，点击「登记渠道对账凭证」，填写原始商户订单号、渠道交易流水号、实际到账日期和对账依据。凭证明确标为财务人工核对。在线回调凭证标为渠道签名通知。同一渠道订单号或流水号只能关联一笔到账。完全相同的重复通知不会再次入账。
3. 核销时若其他收款已抵扣部分余额，剩余实收计入这位长辈的预交账户，并沿用已有的欠款冲抵顺序。月度入款分别计算实收核销和预交到账，预交冲抵单独列示。登记已发生的支出时须填写凭证编号、分类、金额、收款对象及用途。
4. 「欠费提醒」显示服务期已结束且余额大于零的账单。登记实际电话、当面或机构消息的跟进结果后，保留当时的欠款金额。催缴登记不向外发送消息。
5. 「统计报送 → 经营月报」按已授权的业务域展示指标。选择当前月时，环比取上月相同天数，最多到上月月末。选择历史月时，以两个完整自然月对比。经营诊断展示到账笔数、最大支出类别、待执行工单和物资领用品种。点击「对比明细」可核对两期单据。
6. 「统计报送 → 民政报送」生成草稿并核对问题，下载加密的 `.akdoc`。授权的总部报送人员在本机构「民政报送 → 打开加密文件」调阅。接入当地民政系统时按受控接口与报送渠道送出。登记实际接收方与送出凭证后固化该版快照。接收方退回时登记回执号及原因，补正源数据后生成下一版。已送各版可单独导出，已受理月份保留签收版本。当地政务平台的字段、域名、证书和正式接收回执由接收机构提供。

民政月报的照护运营汇总面向本期在院服务对象。计划工单按计划日期归集，有效完成量按完成日期归集，实际服务人数按已完成工单中的长辈去重。旧工单缺少完成日期时按计划日归集。补正前各次已送快照均保留当版汇总。

## 入住交费与预缴金

财务权限账号办理正式入住、试住或试住转正后会打开「入住交费」。试住使用已生成的一次性收费单。正式入住可在同一窗口核对首期月费明细、生成账单，再点「已交费 · 登记收款」或「收款二维码」。若首期计费日尚未到，可先登记实际已收到的预缴金。其他财务人员可从「财务管理 → 收费账单 → 查看明细」继续收款。

桌面版点击收款码下的支付链接时，会重新核对当前订单。已付款或已过期时需核对账单；仍可付款时由系统唤起微信或打开支付宝官方收银页。

财务管理的「实收流水」按到账日期逐笔展示，支持查看今日、本月至今、全部或自选时段。每笔实收的账单核销和转预缴列于同一行。旧凭证的手续费未记载时，对应净入账显示待核对。

总管理员在「财务管理 → 收款手续费设置」维护微信支付、支付宝、银联刷卡、银行转账的签约百分比。首次设置前费率为零，现金固定为零。财务登记时选择实际方式，例如「线下登记（微信支付）」或「线下刷卡登记（银联刷卡）」。人工登记微信或支付宝到款时须填写实际到账日期、商户订单号及渠道交易流水号。签名回执与财务补登记按原订单和交易号核对，先后顺序不会改变总实收。

每笔凭证以长辈实交的毛额核销。机构承担手续费，净入账为毛额减去按整笔舍入到分的手续费。线下登记保存当时费率，渠道单保存开单时费率，后续改价不影响原始明细。历史凭证没有记载费率时显示为「—」。同一账单收到多于欠款的金额时，核销后将结余计入该长辈的预缴账户，优先冲抵其他待缴单，剩余款留至之后的账期。已有预缴优先抵扣，催缴凭证按抵扣后的余额出具。

例如，账单待缴 50.01 元，线下刷卡实收 100.99 元，费率 0.60%。账单结清，50.98 元转入预缴，机构承担 0.61 元，净入账 100.38 元。账单核销和预缴明细按同一凭证编号关联，分别记载各自的手续费和净额。再次冲抵预缴余额仅作核销，经营流水只计原始到账一次。

## 电费和银行支出文件

全机构财务人员在「财务结算 → 支出登记」打开「导入银行或电费凭证」，选择来源并下载该来源的 CSV 样例。确认行以后才写入支出流水。河南政务服务指引列出了网上国网 App 和国网河南省电力公司微信公众号的电子发票下载方式。原件记载开票时，仍需核对实际付款信息。[河南政务服务用电指南](https://www.hnzwfw.gov.cn/portal/guide/4C13CEA50C56B2EE3A64C68BF54BD747?region=411300000000) · [财政部电子凭证会计数据标准](https://kjs.mof.gov.cn/zt/kuaijixinxihuajianshe/dzpzkjsjbzshsd/sjbz/202505/t20250519_3964020.htm)

| 来源 | 必需的核验信息 | 可选信息 |
| --- | --- | --- |
| 银行 CSV | 交易日期、银行流水号、对方户名、明确的借方支出与金额。支持「借方发生额」「贷方发生额」双列，也支持「收支方向」「交易金额」 | 币种、交易状态、摘要、发票号码、支出分类 |
| 电费缴费 CSV | 缴费日期、实付金额、收款单位、已缴费状态、发票号码或银行流水号 | 两种凭证编号同时提供便于跨文件对账，可附摘要 |
| 电费数电发票 XML | 可识别的唯一发票号。确认关联已登记支出时，还须能提取与实付相符的收款方、含税金额 | 对不能确定实付的发票，先核对银行流水或缴费明细，再关联原件 |

CSV 文件支持 UTF-8 和 GB18030。每个文件最大 1 MiB，每个 CSV 最多 1,000 条。贷方收入、退款与未实付记录分别排除或标为待核对。相同发票号码或银行流水号在金额、收款方等凭据相符时可以追加原件，新增支出金额为零。同日、同额、同收款方的手工或跨来源记录缺少共同凭证号时，预览列出候选凭证号、来源和日期供财务比对，可保留待核对。同一银行流水号存在相互冲突的实付日期时也会列入待核对。凭证仅从本次上传的文件读取，确认后在机构加密数据库内保存原始文件，可从相应支出行下载。

- `POST /api/finance/expense-import/preview` 传入 `source`（`bank` 或 `electricity`）、`fileName` 与文件原始字节的 `contentBase64`。响应含 30 分钟有效的 `previewId`、当前业务版本及逐行核对结果。
- 确认时经 `/api/commands` 提交 `ops.importExpenses`、当前业务版本、`previewId` 和勾选的 `rowNumbers`。服务端重新检查经办权限和已登记凭证，并在单个事务内保存支出及原件。业务版本已改变时应重新预览。重复提交同份已登记凭证不会产生第二笔支出。
- `GET /api/finance/expense-import/files/{id}` 由全机构财务账号调取该笔已确认的原始账单。响应为附件原始字节。所有确认的附件随机构加密快照备份。

## 账单分段规则

- 正式入住采用月付。每月账单日默认取正式入住日的日号，办理时可在 1 至 31 日中选定。入住首期自服务开始日计至下个约定账单日前一天，例如 11 月 11 日入住、约定每月 20 日出账，首期为 11 月 11–19 日，第二期为 11 月 20 日至 12 月 19 日。两个账期可归于同一月份，核算时以具体账单日区分。月底不足约定日的月份取当月最后一天，下月再按原约定日计算。历史未约定账单日的档案沿用原自然月。
- 到达账单日后，「财务结算」列出各长辈最早待核算的月付账期。财务审核项目、起止日期及金额并确认生成应收。日费随床位和已审核通过的照护等级生效，同日多次变动取当天最后一次已生效状态。账期内已退住的截至实际退住日，在住的按本期末日及当前已知的安排预估。
- 设置押金后，仍可在「收费账单」及「待出月账单」核对月费，站内账务提醒在合同到期或押金实际冲抵时送达。经单独授权的家属可查看绑定长辈的提醒。固定期限的下一个待续月费账期足额结清时，合同从原到期日顺延一个月。已用押金冲抵的账单，由经办人核对续住。收费账单明细和长辈档案的续住记录均保留变更前后的到期日。
- 试住登记确认时生成一张约定总价的一次性收费单，可用原有收款、预交冲抵及渠道对账。试住期间不生成正式月费。转正后，月付服务从实际转正日与试住套餐预计离院日中较晚的日期开始。例如 24 日试住 3 天 2 夜，25 日提前转正，24、25 两夜仍属于试住套餐，月付从 26 日开始。结束试住后没有后续月账。
- 床位费按入住日数收取。护理费按服务日期逐日计收，请假日保留床位并免护理费。账单明细显示每段日期、床位、等级、两项单价、服务日与请假日。账单生成时冻结该次核算的价格及分段。
- 财务可按合同另填床位、护理日费或约定请假天数。若整月护理单价不同且人工请假天数与请假台账有出入，须先补齐请假日期，或按合同提供统一护理单价。新入住、转床与等级审核记录保存当时的计费条件。旧记录缺少当时单价或等级时，使用可查的床位定价和档案护理等级回算。

## 商户通知端口

支付收银侧须把商户通知指向机构公开的 HTTPS 服务。机构工作台按 README 配置受信域名。签名使用独立的商户配置，所配公钥、商户号、应用号必须属于本机构签约的对应支付渠道。回调验签使用服务端加密依赖 `cryptography`。微信 APIv3 密钥文件由部署方保管。

| 渠道 | 接口与成功应答 | 服务端配置 |
| --- | --- | --- |
| 微信支付普通商户 APIv3 | `POST /api/payments/notify/wechat`，JSON；成功返回 200。校验微信支付公钥 ID、时间和原始报文 RSA 签名，再用 AES-256-GCM 解密成功交易。 | `NH_WXPAY_PUBLIC_KEY_FILE` 指向微信支付 RSA 公钥 PEM，`NH_WXPAY_PUBLIC_KEY_ID` 对应公钥 ID，`NH_WXPAY_V3_KEY_FILE` 指向 APIv3 密钥文件，另配 `NH_WXPAY_APP_ID` 和 `NH_WXPAY_MERCHANT_ID`。 |
| 支付宝普通直连、UTF-8、RSA2 公钥模式 | `POST /api/payments/notify/alipay`，表单编码；成功返回文本 `success`。验签后核对 `app_id`、`seller_id`、付款状态、币种、原始订单和金额。 | `NH_ALIPAY_PUBLIC_KEY_FILE` 指向支付宝平台公钥 PEM，另配 `NH_ALIPAY_APP_ID` 和 `NH_ALIPAY_SELLER_ID`。 |

微信通知签名验证原始正文及平台请求头。支付宝按官方 SDK 对业务参数排序，由 RSA2 验签。未登记的订单、签名不正确、金额或商户不匹配均返回非成功状态，不产生收款流水。测试在临时库使用独立生成的密钥和签名通知。商户联调须使用机构授权的密钥和收银系统。[微信支付回调文档](https://pay.wechatpay.cn/doc/v3/merchant/4012791836) · [支付宝官方 SDK 验签逻辑](https://github.com/alipay/alipay-sdk-java-all/blob/master/v2/src/main/java/com/alipay/api/internal/util/AlipaySignature.java)

## 可选商户收款码

在服务端的运行环境安装 `python3 -m pip install -r requirements-payments.txt`。设置 `NH_PAYMENT_PUBLIC_ORIGIN` 为由机构提供 HTTPS 反向代理的根域名，例如 `https://care.example.org`。按上表配置到账通知的商户身份及验签材料。

| 收银渠道 | 补充配置 | 申请与核对 |
| --- | --- | --- |
| 微信 Native | `NH_WXPAY_PRIVATE_KEY_FILE` 指向商户 API 证书的 RSA 私钥 PEM，`NH_WXPAY_CERT_SERIAL` 为对应商户证书序列号。 | 财务工作台向微信 Native 接口签名下单并校验平台应答签名，在本机将 `code_url` 编为二维码。 |
| 支付宝当面付 | `NH_ALIPAY_PRIVATE_KEY_FILE` 指向应用签名私钥 PEM，配合平台侧已登记的应用公钥。 | 工作台调用 `alipay.trade.precreate`，验证应答正文的 RSA2 签名、结果码和商户订单号，在本机将 `qr_code` 编为二维码。 |

可用渠道由服务端根据收银组件、商户配置和密钥文件的可读性决定。财务操作需要登录且具备财务权限。首次取码和到账分别记录审计。重复打开有效二维码沿用同一商户订单。同一订单并发申请只发出一次。付款页面每四秒检查本地实收状态。订单金额、商户、费用描述及回调地址均由服务端生成，无需向渠道提供长辈姓名或病历。机构上线时须开通对应收银产品，并使用机构自己的商户账号核对公网回调和实收对账。[微信 Native 下单接口](https://pay.wechatpay.cn/doc/v3/merchant/4012791877) · [支付宝官方预下单请求](https://github.com/alipay/alipay-sdk-python-all/blob/master/alipay/aop/api/request/AlipayTradePrecreateRequest.py)

统计报送账号可用 `GET /api/reports/{reportId}/versions/{version}` 读取已登记送出的固定版本。响应包含数据契约版本、机构编号、接收单位、送出凭证、日期和原版数据集。数据集记录入住、退住、期末在住和月内照护运营数量。当地平台的字段映射、签章、传输和回执认证由接收方协议决定。

## 老人收费、费用来源和养老金

核算月度账单时，房间床位费和护理费沿用入住、转床及请假记录。点击「添加费用项」可选择饮食、医疗服务、药品、耗材、康复、洗护、陪诊交通、水电、专项服务、其他约定收费或减免。每项保存单价、数量、单位与金额。按天项目可选择入住天数或扣除请假的在院天数。单价以院方合同或实际凭证为准。提交前可逐行核对合计，院内审核 Agent 在同一事务核对实收、余额及分项合计。历史账单缺少分类的余额显示为「历史账单未细分金额」。

长辈档案中的「费用来源」记录谁承担费用，「养老金收入」记录长辈个人收入。二者可与账单、已到账凭证分别查看。登记长护险经办或子女资助金额不会自动核销账单。

## 前台扫描顾客付款码

现有系统支持在商户签约并配置后向顾客展示商户收款码，以及签名回调对账。前台拿扫码枪读取顾客手机付款码，是另一个可商用的收银场景。两家官方方案如下。

| 商户渠道 | 可申请的接口与现场流程 |
| --- | --- |
| 微信支付付款码支付 | 门店扫码后提交付款码、金额、唯一商户订单号，遇到用户支付中须按渠道规则查单和处理撤销，再将已确认的交易计入实收。[商户 API](https://pay.wechatpay.cn/doc/v2/merchant/4011937125) · [业务流程](https://pay.wechatpay.cn/doc/v2/merchant/4011936672) |
| 支付宝当面付 | 签约条码支付后，收银端读取付款码并通过 `alipay.trade.pay` 提交。以商户签约产品及应用授权为准。[开放平台签约指引](https://open.alipay.com/operatingGuide.htm) · [官方场景说明](https://aipay.alipay.com/article/3074) |

此次完成官方接口选型。顾客付款码被扫扣款上线前，需要院方签约、门店身份和对应收银凭证，以及支付中、断网查单、撤销和到账幂等的商户联调。顾客付款码不得写入长辈档案、工单、Agent 提示、操作日志或备份。
