# 健康助理怎样分工

[文档导航](README.md) · [English](en/agent-components.md)

员工提交一组就诊文件后，可以继续问助理「主楼还有哪些空床？」DeerFlow 在主对话中查床位，另一个 DeerFlow 任务整理这次就诊的授权资料。两项工作各有独立的上下文。院务服务负责调用机构配置的模型，并记录用量。

| 员工操作 | 谁负责 | 如何核对 |
| --- | --- | --- |
| 打字或按住说话问院况、找床位、定位到已筛选的页面 | 院务系统转写语音并限定可用工具。DeerFlow 主对话按模型返回的工具请求推进，云端模型选择资料、组织回答。 | 看回答中的资料和页面按钮。打开表单和保存改动分别由员工操作。[主对话入口](../platform_core/agents/deerflow_chat.py) · [官方工作流的接入位置](../deploy/deerflow/conversation.py) |
| 在聊天中要求整理就诊资料，按按钮上传文件 | 只有提问的员工可以使用这条回答里的上传按钮。院务系统保存上传组编号，调用已配置的 OCR 和分类服务，员工确认类别、长辈、就诊日期及是否补充既有病例。 | 点击该条回答的上传按钮时，用量沿用这次对话的任务编号。直接上传另起一组。 |
| 资料选好后点击「开始识别并核对」 | 院务系统先把原件和任务存入加密库，员工随即可回到对话。DeerFlow 读取这位长辈这次就诊的授权文字，整理字段并检查引用。 | 在「健康助理 → 整理任务 → 核对草稿」按页核对原件。确认后由原有病例签认命令入档。关闭窗口可以继续聊天，重新登录后可找回本人待核对任务。[待办与恢复](../platform_core/visit_jobs.py) · [就诊字段与来源](../platform_core/visit_extraction.py) |
| 每日整理起居、三餐、活动，或查看近期健康变化 | 机构调度器选择在住对象、日期、床位和作业。DeerFlow 写生活简报时读取签认过的生活记录，做健康复核时读取获准使用的本人健康摘录。 | 在档案中核对时间及来源编号，临床复核和家属推送沿用原来的授权条件。[机构巡查](rounds.md) |
| 员工纠正助理的表达或资料引用方式 | 员工可以填写具体的改进意见，也可以点击「从审核记录提议」，让系统参考当前院区、岗位和主题的既往决定。DeerFlow 校验候选规则，在预览中提供版本及内容摘要。员工先用虚构案例核对效果，再提交审核。主对话和定时任务按岗位、院区及业务类型使用已发布版本。 | 在健康助理中打开「改进回答」，或从机构设置中进入规则管理。有审批权限的员工在「审核与记录」中发布、驳回或恢复历史版本。表格整理复用社区的 XLSX Skill，来源和许可见清单。[规则实现](../platform_core/agents/growth.py) · [技能及上游许可](../skills/UPSTREAM.md) |

跨岗位简报的入口是 `agent.start`。自动模式先让云端模型从已授权专员中作出选择，员工也可以直接指定一位专员。DeerFlow 的 `task` 工具按已核准的顺序，从注册表 `custom_agents` 调用护理、库存或财务专员。每位专员只可用 `read_assigned_evidence` 核对本次委派的资料一次。院务服务按当时的岗位和区域读取记录，核对引用，再生成待审简报。上一步未完成时，后续专员不会领取资料。日常聊天、一次就诊的资料整理和定时生活简报各用自己的 DeerFlow 工作流。[主对话循环](../deploy/deerflow/conversation.py) · [专员委派与取证](../deploy/deerflow/delegation.py)

## 交接、恢复和权限

点击助理答复中的上传按钮后，服务端检查员工的登录会话和发起上传的对话。员工确认资料归属后，文档任务只能读取这组原件。主对话和各业务任务共用院务权限服务和已批准的规则，各自按任务准备模型上下文。后台进程只获得本次任务所需的资料，模型密钥和病例签认权限仍由院务服务掌管。

服务重启后，文档工作进程重新领取未完成的任务。原会话失效、人员权限变化或资料归属变化时暂停办理。原经办人重新登录后，只要仍有权访问档案，就能从任务列表继续整理。重试前，服务先核对已有的 OCR 结果、模型回执和草稿。供应商是否完成调用尚不明确时，该笔调用进入待对账流程。

## 部署和用量

部署清单锁定字节跳动 DeerFlow 2.x 的官方版本 `v2.2.0`，源码提交为 `58fc5bd5b8e6ea46538e9481ba06ca2a46e14e2a`。院务服务通过私有管道与执行对话或证据整理的进程通信。Owner 可在「部署控制台 → 健康助理的执行组件」看安装情况，在「机构设置 → AI 用量 → 调用明细」点击任务编号，核对各步骤、输入、缓存命中、输出、OCR 页数和语音用量。旧版由 Pi 执行的对话仍按原回执记账，较早记录可能没有任务编号。[部署步骤](quick-deploy.md) · [DeerFlow 安装](../deploy/deerflow/README.md) · [官方版本](https://github.com/bytedance/deer-flow/releases/tag/v2.2.0)

员工的一条消息最多调用三次工具，后续查询与首次查询共用这三个名额。对话最多带上同一账号、同一授权范围内最近五轮适用的完整问答。跨会话保留的写作经验来自有权限员工发布的院区规则。想核对某条建议的依据，在「审核与记录」展开「查看审核依据」，可以对照提交时的新旧规则、静态检查报告，以及这次提案所用的审核记录。

如果已有社区 MCP 提供所需的只读查询，运营方可在 `NH_MCP_CONFIG` 登记服务、工具名、参数和所需权限。健康助理只把当前授权内的工具交给模型；DeerFlow 连接 MCP 服务后，还会核对对端声明的只读属性。外部应用调用院务 API 时也须使用获授权的机构账号。[接入步骤](assistant-harness.md) · [DeerFlow MCP 客户端](../deploy/deerflow/capabilities.py)

## 一次任务会用多少 token

普通文字提问可以由一次模型调用直接回答。如果模型需要查台账，DeerFlow 先让院务系统执行获准的查询，再根据结果组织答复。就诊资料整理把识别出的原文按行编号，DeerFlow 的模型只返回各字段对应的行号。OCR 按页单独计量，同一份已成功识别的原件可复用回执。定时健康复核发现同一天、同次入住的资料和规则均无变化时，跳过再次生成。

每次调用的 token 数取决于实际问句、授权摘录及输出长度。用量页分别列出命中缓存的输入、未命中缓存的输入和模型输出。OCR、ASR 和朗读按各自的单位计量。查成本时可按任务编号展开经办人的回执。[用量统计](provider.md)
