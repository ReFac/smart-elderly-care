# 健康助理使用与 Agent 交接手册

[文档导航](README.md) · [English edition](en/agent-handbook.md) · [机构业务操作手册](workspace-manual.md) · [Owner 部署控制台](deployment-console.md)

员工可以在同一个对话里先问院况，再发起具体业务。助理把工作交给相应的业务专员，每个专员只读获准的资料，返回答案或草稿供员工核对。部署方可复用社区 Skills，通过官方 MCP SDK 接入审核过的工具，也可让外部 Agent 查询本院已开放的只读接口。

DeerFlow 负责主对话，也运行分开的专门任务。比如，就诊整理只处理同一位长辈同一次就诊的材料，生活简报只读取这位长辈本次入住的签认记录。部署、资料权限与员工签认的分工见[组件与维护说明](agent-components.md)。

国际版可以问“How are things today?”，或说“Open bed management”取得床位管理按钮。法语机构可以问“Comment va la résidence aujourd’hui ?”，西语机构可以问“¿Cómo está hoy la residencia?”。概况中的人数、工单和款项来自当前账号可查看的记录。

## 员工如何使用内置助理

从左栏「AI」、右上角「健康助理」或悬浮图标进入同一个对话。点击答复中的按钮才会打开业务页，助理随之缩小，仍可拖动和继续追问。办完后可以接着原来的对话追问。再次打开大悬浮窗时，它会回到上次拖动的位置。按 Enter 发送文字，Shift + Enter 换行。按住说话，松开后自动整理转写并发送。选中「朗读」可听取语音提问的答复，朗读小窗可暂停、继续或退出。遇到人名、房号、金额和「除了」等例外，尤其要核对转写和业务窗中的结果。[对话与朗读](agent-runtime.md)

| 想做的事 | 可以这样说 | 怎样完成或核对 |
| --- | --- | --- |
| 接班前看院内情况 | 「今天怎么样了？」「过去 48 小时呢？」 | 看答复使用的时间段、已登记事件、尚待处理事项。院内简报通常回顾 24 小时，并说明当前床位等快照。若有权限可追问今日异常和体征覆盖人数。 |
| 查实收、预缴或欠费 | 「这个月流水多少？今天收了多少，还欠多少？」 | 财务人员核对本月实收、今日新增实收及目前待缴余额。打开「收费记录」核对到账日期和凭证。若同一笔费用后来用预缴金冲抵，核实流水时只算一次。 |
| 打开已筛选的页面 | 「打开床位管理，筛选主楼」「如何发送定时批量报单？」 | 点击「床位管理」或「定时工单与批量派发」按钮，核对楼栋、页签与列表。有多栋近似名称时说清分院和楼名。 |
| 转交任务 | 先问「今天护理用具够吗」，需要办理时再说「创建护理用具工单」 | 查库存只产生答复。提出开单后点击审核按钮，填写负责人、数量等，核对并发布。全院通知需要对应发布权限。 |
| 登记本轮服药或用餐 | 「101、102 房的长辈已完成早晨服药，除了……」「今天午餐大家都吃了，某某没吃鱼」 | 点击确认入口，逐人核对床位、餐次或用药轮次、例外与原因；服药逐人确认。查个人时间线核对当餐实际菜品和经办人。 |
| 查操作和公开知识 | 「怎样办理试住？」「找一下养老机构防跌倒指南」 | 平台问题可查「常见问题」。点击联网开关后可检索相关公开资料，引用来源随搜索结果返回。查个人病历或机构流水应使用院内台账。 |
| 办理其他表单 | 「新增员工」「登记生命体征」「给这位长辈办理试住」「登记院务支出」 | 点击对应表单按钮，人工填写必需字段，确认后查业务列表、操作日志或办理凭证。填写权限与当前登录账号一致。 |

**修改助理的写作方式。** 在健康助理中打开「改进回答」，选好院区和主题，填入希望调整的写法，点击「预览修改效果」。也可点击「从审核记录提议」，从当前岗位可用的采纳和驳回记录中找出候选顺序。看过原写法、新写法、虚构示例和 DeerFlow 校验回执后，再提交建议。有审批权限的员工在「审核与记录」点「查看审核依据」，可核对调整前后的规则和 DeerFlow 静态报告，再决定发布或驳回。需要撤回时选择历史版本的「恢复此版」。

**对话如何引用资料。** 助理根据发问人的院区、房间和业务权限选择可读资料。限定某一位长辈时请先核对姓名、档案号和房号。查看个人近况或医疗摘要时，请打开这位长辈自己的原始记录核实。未登记体征的长辈不能计入已测人数。模型最多取回同一权限范围内最近五轮适用的完整问答，较早内容还可在聊天中查看。超过上下文预算时先移出旧问答。交班、角色变化或跨院区查询时，请明确时间和对象。[查询范围与证据](agent-runtime.md)

### 用图片或工作簿整理资料

1. 问「帮我填写一下这个老人的个人信息吧，一张图片可以吗？」或在同一对话中点「上传图片」。有档案编辑权限时也可以点击答复里的「上传长辈资料」。每组可选 1–12 份 JPEG、PNG、PDF 或 XLS/XLSX，每份最大 8 MiB，合计最大 24 MiB。处理完一组再开始下一组。
2. 阅读识别结果，对照原件逐份检查分类。可以改成登记资料、证件、简历、检查报告、处方等，再按「确认分类」。模糊、缺字、数字有冲突时查看对应原页并人工核对。一份证件可能同时适合登记资料与补贴材料，选择要办理的那个入口。
3. **补充个人信息。** 在列表里输入姓名或房号，核对床位后选中本人。把档案原值和识别值放在一起核对，留意规范选项和地址。原件与档案姓名有冲突时，回到选择步骤。新长辈用「用这份资料新建档案」打开同一份完整表单，展开需要的家庭、联系及健康信息。经办人核对并保存后，记录才进入名册。若还要归档证件，在证件或补贴材料窗校对类型、期间及长辈，另行保存原件。
4. **补充病历。** 同一组就诊资料对应同一位长辈的一次就诊，先选本人、再选既往就诊或新建并填日期。核对医院、识别文字、药物医嘱与原始附件，签认后到「长辈档案 → 医疗资料」查看。影像中未附书面结论的内容交临床经办人判读。
5. **简历与劳动合同。** 上传简历后确认文件类别，打开新增员工表单，对照原件核对姓名、联系方式等预填资料。经办人手动选择岗位和权限，最后确认保存。合同应另选对应员工、核对合同和归档目标，再按业务流程保存。
6. **工作簿。** 从助理下载登记工作表，或从 OCR 结果下载带已识别值的工作表。在 WPS、Excel 或 LibreOffice 编辑，第一行为字段名，一行一位。如果工作簿有多张表，把登记页命名为「长辈登记」。每次最多处理 500 行、64 列。支持姓名、出生日期、联系电话、常用语言、婚姻状况、文化程度、原职业、籍贯、出生地、现住址。上传后选择一行，核对来源和档案。公式和未匹配的选项需补充，逐份保存。下载或上传本身不产生入住或收费记录。[资料整理和工作表示例](assistant-harness.md)

**结果看起来不对时。** 如果只有文字没有入档按钮，检查岗位是否具备「健康助理」和所选表单的业务权限。遇到同名、缺失字段或看不到长辈，先确认所属分院和人员范围。有权岗位可按机构流程申请临时编辑授权，审批人需实名签认。上传失败时检查格式、容量和当前是否还在处理另一组。手工办理仍可从对应业务页进入。云端调用失败时保存原件，记录请求编号和时间，由 Owner 查「机构设置 → AI 用量」及服务状态。运营方的模型余额、媒体服务配置、机构套餐和网络故障分别处理。已提交的操作先查凭证再重试。[权限与操作手册](workspace-manual.md) · [供应商与计量](provider.md)

### 给在住长辈安排两项定时整理

| 在哪里操作 | 操作与核对 |
| --- | --- |
| 系统管理 → 机构设置 → 定时巡查 | Owner 在「长辈档案自动整理」分别打开「长辈健康变化」或「今日生活」的「调整计划」。选择启用或暂停，填写 5–1440 分钟的周期，核对对象及时间再确认。从「系统监控 → 定时任务 → 长辈档案自动整理」也可进入。 |
| 同一页的「生成规则与站内提醒」 | 机构可设长辈默认手动或定时生成，以及站内提醒时间。长辈详细档案「疗养院时间线 → 近期变化与建议 → 生成设置」可单独选择「跟随机构」「定时生成」「手动生成」。两项后台任务对本人的自动生成沿用这个选择。 |
| 长辈简易档案，或详细档案 → 疗养院时间线 | 在「近期变化与建议」看本人本次入住的草稿。「今日生活」说明已签认的三餐、起居与活动。健康信息还须有医疗与临床权限，「长辈健康变化」会列出可核对的体征、观察和既有记录。点每条的「查看依据」核对日期、类型及记录编号。较早的生活记录按实际日期显示。 |
| 确认是否已生成 | 在定时巡查页核对上次结果、下次运行时间、排队数和等待重试数。排队数已包含等待重试的任务。档案标明生成日期及模型，有资料但未出现新草稿时先确认人员范围、自动生成方式与计划状态，再刷新查看队列。缺少资料时请补录或核实原始观察。 |

健康变化草稿供有权员工复核。用药、诊断、工单签署及联系家属均按对应业务办理。长辈已授权且家属已订阅时，家属才会收到生活简报的站内消息。只有获授权的员工能看到健康复核草稿。

## 开发与交付 Agent 从哪里接手

工作台采用 Python 业务服务、SQLite/SQLCipher、原生 JavaScript 模块。浏览器中的对话按钮与人工办理入口共享岗位、院区及具体对象的权限。接手新工作目录或排查交付问题时，先明确员工在哪一步遇到问题，再按下表找对应实现。

| 要定位的行为 | 先查的实现 | 应验证的结果 |
| --- | --- | --- |
| 页面、筛选和入口 | [侧栏真值](../web/lib/desk-navigation.js)、[聊天导航](../platform_core/agents/chat_navigation.py)、[结构化筛选](../platform_core/agents/view_filters.py)、[表单动作](../web/features/assistant-manual-forms.js) | 路由和页签真实存在，有权角色点击后打开正确楼栋或表单。无权角色从侧栏、对话、历史按钮和直接请求均无法越权。 |
| 自然对话、范围和工具 | [主对话](../platform_core/agents/chat.py)、[范围](../platform_core/agents/chat_scope.py)、[院内事实](../platform_core/agents/chat_context.py)、[ReAct 工具调用](../platform_core/agents/react.py) | 模型从当前账号可用的工具中选择，根据上一项结果决定是否再查。员工发一条消息，所有步骤累计最多调用三次工具。权限在调用时再验，阅读工具返回值不能提交业务操作。 |
| 图片、工作表和登记草稿 | [照片分类](../platform_core/agents/document_intake.py)、[字段核验](../platform_core/agents/resident_profile_intake.py)、[工作簿适配](../platform_core/agents/resident_workbook.py)、[文件整理卡](../web/features/assistant-documents.js)、[档案编辑器](../web/features/profile-editor.js) | 用虚构原件测清晰、模糊、同名、冲突、无编辑权和多张混合六种情况。对照附件检查最终表单的每项预填值。关闭未保存的草稿后，再确认档案没有变动。 |
| 员工确认、追溯和重试 | [Web 入口](../server.py)、[岗位策略](../platform_core/access_policy.py)、[数据范围](../platform_core/campus_access.py)、[命令与版本](../platform_core/store.py) | 对原始对象、当前版本、账号、操作权限和目标房间一起校验。请求丢失后读取状态和回执，用原请求号与相同参数处理幂等重试。 |
| MCP、Skill 和媒体 | [MCP 适配](../platform_core/agents/mcp_plugins.py)、[Skill 目录](../platform_core/agents/community_skills.py)、[服务商说明](provider.md)、[媒体说明](media.md) | 从配置、权限、可用性到实际调用分别核实；真实联网、语音、图片服务的测试需部署方的供应商和套餐。 |

### 使用已有 MCP 与社区 Skill

1. 在服务 Python 环境安装 `requirements-harness.txt`。在「机构设置 → AI 套餐与识别服务 → 查看助理工具与技能」或 Owner 的 `GET /api/assistant/extensions` 查实验环境实际加载了什么。可先问「多伦多现在几点」，核对时区与工具回执。工作表导出通过独立 Excel MCP 在本请求的临时目录写文件。
2. 增加工具时，先查已有社区实现。将服务及允许的具体工具登记在受信任的 `NH_MCP_CONFIG` 文件内，逐项定义岗位权限、关键词和参数。支持 stdio 与 Streamable HTTP，远端服务需由部署方信任并配置 HTTPS。主聊天只提供明确放行且上游声明为只读的工具。业务查改继续走院区和对象级 API。工具输出是待核对的数据，凭据、档案及任意文件路径不应作为公共检索参数。[配置样例](examples/workspace-mcp.json) · [接入说明](assistant-harness.md)
3. `NH_AGENT_SKILL_DIRS` 指向运营方审核的技能目录。按需加载 `SKILL.md` 与 Markdown 示例，核对许可证、上游版本及适用岗位。内置材料含社区内部沟通、XLSX 整理方法和本地长辈资料流程。Skill 说明操作方法。执行步骤仍需相应业务权限，使用 OCR 结果填表也须保留原件依据。[上游和许可证](../skills/UPSTREAM.md)
4. 文字可按部署设置用 DeepSeek、OpenAI 兼容接口、Anthropic 或 Google。OCR 和公开资料检索当前使用 DeepSeek；语音识别、朗读可分别设置 DeepSeek、OpenAI 或自建 HTTP。逐功能检验实际供应商的媒体格式、增量响应、余额与回执。商用客户使用机构套餐，平台托管与自营环境的设置权限不同。[部署边界](deployment-console.md) · [用量与供应商](provider.md)

### API、故障排查与验收

| 调用或故障 | 怎么检查 |
| --- | --- |
| 对话、语音与资料预览 | `GET /api/assistant/chat` 读取范围和可见历史；`POST /api/assistant/chat/stream` 与 `POST /api/assistant/chat` 提问；`POST /api/assistant/voice` 转写，`POST /api/assistant/chat/speech` 朗读；`POST /api/assistant/documents/preview` 分类；`POST /api/assistant/workbooks/preview` 与 `/export` 办理表格。先看当前登录会话、权限、内容类型和供应商回执。 |
| 指定房间或有审核的简报 | 读取 `GET /api/agent/room-context` 时限定房间。房间建议使用 `POST /api/agent/room-proposals`；有权经办人核对后另行确认。协作接口 `GET /api/agent/capabilities` 给出本账号能力；`GET /api/agent/runs/{id}` 查看证据、事件和当前状态。通过 `POST /api/commands` 办理 `agent.start`、`agent.publish` 或 `agent.cancel`。相同请求保留请求号和参数，版本冲突先读取新的状态及终态。[运行实例及事件](agent-runtime.md) |
| 模型答不出、入口不见、权限中途被撤 | 检查会话、页面权限、院区/房间、最近五轮、导航版本与数据采集时间。已关闭院区或旧权限需要重新读取。公开查找不能代替院内授权查询。检查网络、供应商及机构用量时按服务分别确认，日志使用请求号，避免复制原件、密钥或身份号码。[计量](provider.md) |
| 交付方需要新硬件或外部协作 | 对照能力目录，查看适配器实际返回与网关心跳。兼容目录中标记 reserved 的调用返回 501，A2A 可实查床位与今日工单，外部轨迹导出需单独接入验证。[A2A 对接](agent-protocol.md)。设备实机、商户到账、家属外部推送应有各自渠道回执才可记为已验收。[运行契约](agent-runtime.md) · [交付设置](deployment-console.md) |

以下测试和交付演练限定为简体中文（`zh-CN`）及语言无关的公共能力。在项目根目录安装依赖后，使用隔离测试入口选择适用用例。普通单元测试用临时凭据登录，用模拟响应验证供应商调用。[仓库测试约定](../AGENTS.md)

```sh
export NH_DEPLOYMENT_LANGUAGE=zh-CN
python3 tests/run.py -p 'test_assistant_*.py' -q
python3 tests/run.py -p test_mcp_plugins.py -q
python3 tests/run.py -p test_community_skills.py -q
python3 tests/run.py -p test_resident_workbook.py -q
python3 tests/browser/desktop_workspace.py
```

交付时至少选择一位有权员工与一位受限员工，在虚构档案上复演「提问 → 点击已筛选入口 → 上传资料 → 核对草稿 → 本人保存 → 查日志」。记录所用版本、岗位、院区、输入样例、请求号、预期和实际结果。照片、工作簿或文本答复的回归可以在隔离环境完成；需要商家设备或外部服务回执的步骤应单列实际联调状态。[浏览器文件整理用例](../tests/browser/assistant-documents.html) · [角色切换用例](../tests/browser/workspace_roles.py)

## 如何验收一条 Agent 流程

1. 以具备物资和财务查看权限的员工登录，询问「用工具核对库存和财务到账」。模型可先读取经授权的库存，再查询到账记录。展开「查看使用的工具」可见名称与耗时。工具请求包含未知名称、越权参数或超限调用时服务端拒绝执行。对话记忆隔离到当前岗位和区域，最多五轮；来源、业务状态与恢复点保存在机构加密关系库。
2. 生成一份跨照护、物资的专门简报。在同一请求号下重试，已完成领域从加密检查点恢复。岗位撤权、来源修订变化时重新评估。生成文字的数字及执行声明经过检查，允许一次纠正。最终建议需员工确认后才能发布。这段流程采用 ReAct 的工具观察和监督者与专员的分工，并保存图工作流的进度供重试。[流程设计](https://www.anthropic.com/research/building-effective-agents) · [持久化设计](https://docs.langchain.com/oss/python/langgraph/persistence)
3. 用测试员工调用 [A2A 服务](agent-protocol.md)，记录任务号，重启后取回。更换账号验证访问被拒。部署新的 MCP 或技能时检验允许的工具、参数、岗位、数据出境与超时；向模型提供的原件文字及工具输出仅作为数据，不具备指令权限。
4. 使用服务的 Python 环境运行 `python tools/evaluate_agent.py`。可用 `--group chat`、`workflow`、`tools`、`documents` 单组评估。测试使用临时库、模拟云端回执与真实 SDK；评估维度涵盖权限拒绝、额度、云端异常、重复请求、人审、检查点和中文文档。模型效果需在获授权的独立样本上另测事实正确率和人工改动率。机构不限量时仍逐笔计量，模型或工具没有回执的交易留待对账。
