# Owner 部署控制台

[文档导航](README.md)

以 Owner 登录，打开左侧一级入口「部署控制台」。页面展示运行版本、机构类型、当前模型、凭据配置状态、付费套餐、网关最近心跳，以及配置变更的经办人和时间。「已配置」表示后台有凭据。实际模型调用还需要有效套餐、供应商账号及网络连接。

## 平台托管和自营部署

| 运行环境 | 机构 Owner 可以操作 |
| --- | --- |
| `NH_DEPLOYMENT_MODE=managed`（默认） | 查看当前模型与平台套餐、查看用量、管理本机构的设备网关。供应商密钥及模型端点由平台运维配置。 |
| `NH_DEPLOYMENT_MODE=operator` | 编辑模型、部署端口、应用策略，管理网关。仅在由本方信任的 Owner 控制的独立服务进程中启用。 |
| `NH_INSTITUTION_PROFILE=licensed-medical` | 控制台展示「持证医疗机构」，普通版展示「养老服务机构」。部署资质由宿主环境指定。 |

通过反向代理开放的正式机构使用 HTTPS 公网源。例如在已完成数据库、Owner 密码与密钥初始化的服务目录运行：

```bash
NH_DEPLOYMENT_MODE=managed python3 manage_updates.py run --initial-data empty --db .local/institution.sqlite3 --public-origin https://care.example.org
```

每个机构独立使用一个服务进程、业务数据库和运维库。在 `operator` 模式点击「编辑部署配置」，可选 DeepSeek、OpenAI 兼容服务、Anthropic 和 Google。内置服务商对应固定的官方端点，DeepSeek 使用平台定义的模型别名。自建服务通过宿主的 `NH_DEPLOY_CHAT_ENDPOINTS` 登记完整 OpenAI 兼容 Chat Completions URL，多个地址用逗号分隔，HTTPS 或回环 HTTP 适用。自建端点需输入单独的凭据。更换端点时原端点的密钥不会用于新端点。输入框留空时沿用已配置的同端点凭据，官方端点也可沿用宿主凭据。对话、OCR、语音和朗读服务的对应关系见[服务商配置](provider.md)及[语音与文书设置](media.md)。

## 保存、批准与重启

1. 核实运行值，填写目标监听地址、端口和模型。默认绑定 `127.0.0.1`；如容器反向代理要求，运维先在宿主配置 `NH_DEPLOY_ALLOW_NETWORK_BIND=1` 和 `--public-origin https://机构域名`，再通过私有网络与防火墙限制后端，仅允许反向代理接入。
2. 「保存后另行批准」创建待应用配置。「批准下次启动应用」或保存时选择「下次重启时应用」后，安排运维窗口重启服务。页面上的「撤回配置」可取消待应用变更。
3. 更新托管启动器或 systemd 必须重启整个托管服务。启动命令显式填写 `--port` 时该参数优先，界面显示固定端口。希望通过控制台管理端口时省略它。相同机构只能有一个运行服务。监听变更后同步修改反向代理的上游端口。
4. 重启后重新打开控制台核对监听、模型和变更记录。端口占用或端点已从宿主许可名单移除会导致启动失败。可使用之前已知可用的 `--port` 临时启动以检查、撤回或修正待应用设置。如配置整体损坏，使用 `NH_DEPLOYMENT_MODE=managed` 和固定端口及宿主凭据启动，再脱机恢复运维库。

控制台写入相邻的专用 SQLCipher 运维库，文件名为 `.<业务库文件名>.deployment.sqlite3`。其加密密钥默认与该文件同目录，也可由 `NH_PLATFORM_KEY_FILE` 指定。机构业务快照不包含部署库。请在受控停机窗口把部署库及独立密钥分别保存到运维恢复介质，并验证可以恢复和读取。API 密钥不通过接口回显，变更记录只保存经办人、时间和操作类别。

## 设备连接

在「设备网关连接」登记设备编号、名称、接入方式以及边缘网关的 32–128 位随机专用令牌。允许字母、数字、短横线和下划线。修改现有网关时留空可沿用令牌。停用或轮换立即使原凭据失效。在边缘设备配置由控制台显示的心跳路径，每分钟上报一次：

```http
POST /api/deployment/gateways/radar-1/heartbeat
Authorization: Bearer <设备专用令牌>
Content-Type: application/json

{}
```

使用 TLS 反向代理或同机回环连接传输令牌。成功回执包含 `accepted` 及服务端接收时间。首次收到已验证心跳前显示「等待首报」；三分钟内有上报显示「近期收到心跳」，超过三分钟显示「心跳超时」。点击「刷新状态」可重新采样。MQTT、Modbus 由边缘网桥转发上述 HTTP 心跳。心跳验证设备连接；设备的厂商业务适配、事件语义、床位绑定与预警链路需独立联调。
