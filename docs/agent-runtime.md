# 云端健康助理与业务接口

[文档导航](README.md)

在电脑端打开右上角的「健康助理」，问「今天养老院情况怎么样」，再接着问护理情况或用品库存。需要创建工单或发布全员通知时，点击答复中的按钮，到业务页面核对并确认。已有调用方可使用下列接口生成并留存专门简报。

## 对话、定位与人工发布

电脑端的「健康助理」共享同一份院内台账。问“今天养老院怎么样”会取最近 24 小时已授权的变动与当前床位、照护和库存等概况，继续问“过去 48 小时呢”会切换时间窗。DeerFlow 负责主对话的工具调用，也负责资料分类、简报撰写和交班核对项排序。模型密钥、院内工具和用量账本由院务服务掌管。[运行组件](agent-components.md)

如果发问人的区域、岗位或可查对象发生变化，服务端会按新范围隔离对话。服务端从授权台账选取必要字段，连同相关问题送往 DeepSeek。

- `GET /api/assistant/chat` 读取本账号当前范围的对话，并返回范围键、会话版本与 `memoryTurns`。
- `POST /api/assistant/chat` 接受问题、客户端请求编号、当前页和可选区域。模型最多接收当前问题之前最近 5 轮已完成问答中的有效上下文，较早记录仍可在界面查看。上下文超过输入预算时按完整问答缩减。超出服务范围的提问在工作台直接答复。
- 健康助理按 ReAct 的工具调用与观察流程核对相关事实。一条员工消息累计最多调用三次工具。模型可以根据第一次查询结果再选工具，服务端逐次核对权限、区域、参数和请求状态。打开「查看使用的工具」可以看到工具名称、耗时及是否成功，模型调用的用量按实际回执入账。审批界面展示业务结果与依据。
- 院内答复可以附带 `pageLinks`。每项的 `route` 标识业务页面，`title` 用作入口文字，可选的 `tab` 定位到具体页签。例如总管理员问“备份记录在哪里看？”，点击回答下方的入口会打开「机构设置 → 备份与恢复」。点击前保留当前页面，重新打开对话后仍可点选当前账号有权访问的入口。
- 开启右下角的联网头像后，可以检索养老机构运营、长护险、照护及相关医疗的公开资料。对话回复使用 `webSearched` 标明实际检索状态，院务答复继续沿用已授权台账。[接口与计量](provider.md#公开网页搜索)
- 文字和语音共用一个对话窗口。按住说话，松开后自动转写并发送。录音前或按住期间可勾选「朗读」。语音提问凭转写回执经 `POST /api/assistant/chat/speech` 分段调用 DeepSeek TTS。朗读小窗可暂停、继续或退出。[语音接口](media.md)
- “创建老人入住”会定位到入住管理名册。“护理用具怎么样”只查询；“创建护理用具工单”打开审核表，要求选择负责人；“发布全员通知”要求全机构通知发布权限。发布命令会重新核对建议来源、账号权限、目标区域和是否已办理。关闭审核窗可以继续聊天。

## 已落地的处理链

| 环节 | 实现与核验方式 |
| --- | --- |
| 业务目标与委派 | 协作接口按岗位和范围确定可用业务域。自动模式将识别出的业务词和获准的专员代号交给 DeerFlow，由机构配置的模型选择最多三个业务域。旧客户端的 `planning: "platform"` 仍可沿用。手工选定专员时直接核对岗位授权。院内工具读取获准的照护、物资和收费数据，每个业务域由 DeepSeek 根据该域统计撰写说明。 |
| 工具与输入 | 照护使用 `care.review`，物资使用 `stock.review`，财务使用 `billing.review`。每个工具接收所声明集合的字段副本。指定某位长辈时，照护输入进一步按长辈编号限定。 |
| 简报与证据 | 每份产物包含专员、工具、标题、说明和证据清单。宿主在写入前核对专员、工具、类别及长辈归属，并按调用前获准读取的记录编号验证每项证据。记录标签与计算值随简报保存，工作人员负责核实结论。运行保存来源工作区版本，历史简报保留当时的值。 |
| 运行轨迹 | SQLite 逐条记录委派、工具调用、产物、待确认和终态事件。打开详情可按序号查到各执行节点和上级节点，从每份产物追到生成它的工具调用。 |
| 暂停与恢复 | 产物产生后进入 `awaiting_approval`，跨服务重启保留。登录人员核对后可发布为 `published` 或取消为 `cancelled`。暂停位置在简报生成与人工决定之间。 |
| 权限与并发 | 员工可查看自己发起且仍拥有全部相关权限的运行。总管理员可跨员工复核。服务端在每次读写时按当前账号重新判断权限。SQLite 事务和工作区版本共同约束发布，同一运行只产生一组建议。 |

照护限定上下文、工具输入字段和财务计算规则可分别从运行时与业务函数追到实现。扩展协议位于独立模块。[协调运行时](../platform_core/agents/runtime.py) · [专员与工具协议](../platform_core/agents/contracts.py) · [审批检查点](../platform_core/agents/__init__.py) · [业务计算与证据](../platform_core/operations/assistants.py)

## 照护计划与自然语言查账

兼容工具 `care.planDraft` 根据在住长辈的有效评估、生活支持需求、照护安排、责任人和复评日整理引用，DeepSeek 依据核对项数量生成业务说明。工作人员核对依据后决定是否发布。需要办理实际工单时，进入照护计划。

财务账号可问“本月实收多少”“2026年10月营收”或“去年收入”。`finance.revenue` 只读取授权范围内的到账日期、渠道、金额和凭证编号，按日、月或年度合计。实收包括直接收款和收到的预交款。后来用预交款冲抵账单时，这笔钱已经计入实收。查询“营收”或“收入”还显示期间开单应收，可同时核对两种金额。每种来源最多列出十笔凭证。业务简报使用云端模型解释已核算的指标。

## API 与重试

| 请求 | 行为 |
| --- | --- |
| `GET /api/agent/capabilities` | 返回当前登录人的工具、业务域、最大步数、运行模式及可见适配器。模型为 `deepseek-flash`，`planningModes` 返回 `platform`，`plan` 提供机构可用性。 |
| `GET /api/agent/runs` | 返回当前账号可见的最近运行摘要，最多 80 条。 |
| `GET /api/agent/runs/{id}` | 返回当前状态、来源版本、简报、证据和有序事件。缺少智能助手权限返回 403。持有该权限但无权访问指定运行时返回 404。 |
| `POST /api/commands` | `agent.start` 创建运行，`agent.publish` 发布简报，`agent.cancel` 取消。三个命令均需当前会话及整数工作区版本。 |
| `POST /api/agent/adapters/{id}` | 已登记且可见的预留适配器返回 501 及 `not_connected`，可用目录随角色变化。 |

先读取 `GET /api/state` 获取当前 `revision`，再发起任务。例如工作区恰为版本 12 时，可以提交如下 JSON。自动规划可省略 `scope`。照护任务可传入已登记的 `residentId`。

```json
{
  "action": "agent.start",
  "revision": 12,
  "payload": {
    "goal": "复核护理交班和库存",
    "scope": "auto",
    "requestId": "handover-2026-11-24-am"
  }
}
```

同一人重试时应保留同一个 `requestId` 和相同任务参数。成功提交后，从运行列表取得 `id`，在详情中核对证据。发布或取消的 `payload` 为 `{"runId":"实际运行编号"}`。遇到 409 应刷新版本和运行状态。若已到终态，界面显示最新决定并结束重试。执行中途发生错误时，本次运行、已产生的步骤和工作区修改一起回滚。

## 操作日志中的任务归属

单人照护任务在创建时会从床位记录中取出长辈当时的房间，随任务保存。即使长辈随后转床，任务的发布、取消和发起记录也保留在同一房间。全院任务及同时使用物资、财务等机构级数据的协作任务进入机构级日志。房间筛选与操作人筛选可以组合使用。

总管理员可查全机构日志。员工查自己的协作日志，须具备审计、Agent 协作及该次运行实际涉及的每一项业务权限。撤回其中任何一项后重新查询即生效。历史日志如缺少可核验的运行关联，仅对总管理员可见。[房间与权限回归测试](../tests/test_agent_audit.py)

**AI 工程简历示例**

> 为养老机构管理系统实现带人工审批的多智能体工作流。用 Python 将任务分派给照护、物资、财务三个受权限约束的专员，为简报关联工具、源记录与当次计算值。用 SQLite 持久化审批检查点，通过真实会话的并发和重启测试验证同一简报只发布一次。

面试演示时可发起一次同时涉及交班和库存的任务，先打开简报中引用的原记录，再重启服务，恢复待确认任务，最后用两个客户端尝试发布。可直接核对的结果是两次工具调用、两份待审核建议和一次发布事件。模型效果、节省工时及生产规模应在有对应数据后单独报告。

通过兼容命令 `agent.start` 提交专门简报时保留同一个请求号，复用同一请求的回执。所有业务简报均需可用的 DeepSeek 服务。开通和故障对账见[平台套餐说明](provider.md)。

护理人员输入“查看我待签收的交班”时，照护专员调用本地只读工具 `handover.pending`。工具以已登录账号为接班人，返回待签收总数和最近 10 条交班的记录编号。指定房间、楼层或长辈时，先按当前入住关系过滤，全院交班不计入区域结果。工具只读取编号、日期和长辈关联，工作摘要、体征、签收备注留在业务台账。简报保存查询当时的结果，接班人员打开业务记录核对最新状态并签收。

点击引用时调用 `GET /api/agent/runs/{runId}/handovers/{handoverId}`。服务端再次核实请求人的账号、岗位、简报引用和长辈当前所在区域，然后按查阅权限打开交班详情。签收需要另行确认。

## 房间范围与本地工具

在床位管理中选择楼层或房间，可在所选范围内询问助理。范围随运行保存在 SQLite 中。照护和财务工具只计算该范围当前在住长辈的工单、评估或账单。尚无位置归属的物资只在全院任务使用。查历史账单时，按长辈现居区域汇总。查房间审计时，按事件发生时的床位汇总。

`GET /api/agent/capabilities` 提供登录人的本地工具、业务命令和规划方式。通过 `GET /api/facility/search` 本地搜索姓名或房号。通过 `GET /api/agent/room-context?roomId=…&limit=12` 取得可操作工单的目标编号、字段与权限条件。提交 `POST /api/agent/room-proposals` 时提供 `revision` 以及仅含 `roomId, taskId, note, requestId` 的 `payload`，服务端在写事务内重新核对房间、当前入住和工单，随后进入现有人工确认队列。这些查询和草稿均零模型调用。每个客户使用独立机构数据库，后续可通过受信的服务端 `Store(..., facility_policy=...)` 接入细粒度区域授权。该扩展约束房间与 Agent 接口；原有临床、财务等管理模块继续执行其现有岗位权限。

明确的页面、手填表单和单一床位筛选指令，经服务端核对权限后随流式回答的首帧发出入口。员工可先点击入口打开页面，模型会继续完成答复。开启朗读时声纹小窗会随之继续播放。打开入口前，工作台核对当前账号、权限和版本，有变化时才重读完整工作台。办理业务仍需在对应表单核对并确认。

## 分步生成、证据复核与恢复

发起跨岗位简报时，系统在同一来源版本上核对各步骤可以读取的资料，并按专员保存已核验的结果。使用原账号和原 `requestId` 重试，可继续尚未完成的步骤。每次恢复和修正前重新检查账号、业务权限、区域及来源版本。来源已变更时需要新请求。查询 `GET /api/agent/workflow-progress?requestId=…` 可看到当前版本、计划步骤和已完成步骤，完成后返回可在原流程核对的运行编号。

生成的说明先与该步骤的证据值比对，检查数值、部分常用业务单位，以及宣称已经派发、扣款或修改档案等执行性表述。如果发现问题，模型只能根据同一份授权证据修正一次。再次未通过检查时，系统只显示可核对的本地证据，并提示人工复核。运行详情的 `reflection` 记录结果、尝试次数和触发的检查，事件中会标记复用的已完成步骤。该检查覆盖列出的规则，语义、医学结论及发布决定仍由有权限的人员核对。

模型调用继续使用原有计量与请求回执。已完成的步骤可以从加密检查点恢复。若供应商调用结果不明，须先查清用量回执。保存正式简报及清理中间检查点在同一事务内进行。工作人员确认发布前，系统不会向建议台账写入该简报。
