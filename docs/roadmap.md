# 智慧医养平台实施计划

这份计划以《智慧医养管理平台》PDF 的文件页码为索引。封面算第 1 页，文件第 2–10 页对应内页印刷页码 01–09。试点库从安康家园本部起步，可增设分院及多栋建筑。桌面验收使用虚构长者与文书。后续每个迭代都从已有业务记录出发，以可重放的验收场景收尾。

## 第一阶段 · 机构基础框架与分院扩建

**交付对象**为内部演示人员。运行和验证命令见根目录 README。以下脚本供产品、护理、财务共同走查，阶段结论要记录业务主键、输入、实际输出及待定规则。

| 场景 | 操作与验收证据 |
| --- | --- |
| 接待与床位 | 先建立未入住档案，再从该档案办理入住并选择空床。切回床位视图，核对入住人。尝试占用同一床位，再办理转床或退住，核对床位释放及关联档案。 |
| 档案与评估 | 选择同一在住长者，登记演示评估，记录等级、复评及照护信息。核对个人档案关联的评估和任务。业务人员另行核定正式量表及评审口径。 |
| 照护与交接 | 从当班任务登记执行结果，录入体征或异常并检查留痕。下一班按长者核对待跟进事项。保留未完成任务用于检查跨班显示。 |

### 初稿的财务与报送口径

- 计费使用自然月。入住日和退住日均计入。未退住的当月账单按月至月末预估。床位日价乘入住天数，护理日价乘扣除请假后的天数，月套餐按账单确认金额收取一次。按入住与请假区间的交集逐日减免，同一天只计一次。示例规则需由机构财务核定。
- 默认床位日价取床位记录中的日价或演示默认值 60 元。示例护理日价按自理、半失能、失能取 20、45、70 元，生成账单时固化单价和护理等级。允许录入机构确认的单价、套餐费及请假天数。一个长者每月一张账单。
- 预交款按账期从早到晚冲抵，可用余额保留在长者名下。线下核销必须引用具体账单。预交收款流水和账单冲抵流水应分开汇总，以免把同一笔资金计为两笔收入。
- 报送选取与账期有交集的入住记录，当月统计截止操作日，历史月份截止月末。草稿保存长者编号、入退日期、状态、人数汇总和质量问题。再次生成同一月份会刷新原草稿。冻结版本关联送出、登记回执和退回后的重报记录；真实系统的签章、自动传输和受理确认需要主管部门支持。

### 三类建议的复核依据

每条建议保存生成日期、规则版本、中文结论和当时引用的记录编号。打开建议详情可核对依据。审核只变更建议状态，实际执行仍由对应业务岗位另行登记。

| 类别 | 输入与判断口径 | 核对样例 |
| --- | --- | --- |
| 日常照护 | 读取长者档案、截至当日最近一次评估及复评日，列出当日和过期的待执行工单，优先提示最早到期的任务。缺少评估时提醒经办人核实。 | 完成一张待办后再次生成，核对待办数减少、原建议仍保留生成时的依据。 |
| 物资管控 | 对每种物资比较最近 7 天与此前 7 天的实际出库量。计划目标取库存下限与近 7 天出库量的较大值，建议补量为目标减当前库存，最低为零。当上期至少有 3 笔出库，本期达到上期单笔中位数 3 倍的领用进入复查。 | 首稿护理垫近 7 天出库 13 包，上期 5 包，库存 8 包，建议补充 5 包。可沿库存条目与流水编号核对。 |
| 运营分析 | 分列全部待缴、服务期结束仍有余额的账单。逐笔重算床位、护理及套餐金额，核对已收加待缴等于应收，再比较账单固化日价与等级示例标准。合同另议价可由财务确认。 | 对有单价例外的演示账单检查其编号、账单日价与示例标准。核销已到期账单后再生成，核对欠缴集合变化。 |

## 第二阶段 · 已交付功能的院内试点与规则签认

**前置输入**包括院区床位表、人员与资质、量表授权及版本、照护任务模板、收费目录、请假政策、药品字典和脱敏的历史对账样本。护理部签认评估、用药及交班规则，财务签认费用公式。

1. **护理与评估**。现行版已保存量表版本、26 项评分、来源、签署依据和复评日，并生成待复核的照护计划。试点时按院方人员资质核验服务分配。以离线补录、两班交接、复评改变等级三条案例核查版本和计划执行记录。
2. **床头卡与服务质量**。在首稿分配卡号与床旁核验基础上，对接机构设备、人员身份和岗位执行权限。测试转床后旧卡、重复扫码、超时补录。围绕已执行服务登记抽检、评价、整改与复核。用到期续住清单办理一笔续住和一笔退住，结余费用按机构确认的清算规则核对。
3. **照护与用药安全**。接入经药师复核的过敏原、药品同义名、相互作用及规则版本。将体征、异常和医嘱归入一份可追溯记录，按岗位派发复核，保留撤回、漏服和重复提醒处理结果。用药相关验收由药师提供标准用例并复核。
4. **运营核算**。复核现行分段账单对转床、等级变更、请假和退住的生效日期处理。调账、退款和关账以机构后续签认的财务政策另行验收。验收覆盖跨月请假、月中转床、已缴后退住、重复收款、押金抵扣与整月对账。库存扩展批次、调拨、盘点差异，排班累计工作量与班次交接。
5. **经营分析**。为入住率、护理工作量、领用消耗、应收实收及欠费建立含日期、分母、数据来源的指标字典。现有分院岗位可查询本分院住户账单，机构快照用于数据恢复。后续为经营月报补充按分院对比及历史口径，记录所用数据版本。每个指标都能核到生成它的业务单据，月度诊断标明对比期和异常明细。

**退出条件**为同一套回归样本通过护理、药房、财务与运营四方验收，争议规则有书面版本和生效日。

## 第三阶段 · 人员授权、联动与智能辅助

**前置输入**包括机构及员工身份源、长者家属关系与授权书、计费签约参数、经脱敏的文书样本、模型供应方授权、标注样本与专业审查团队。

| 工作包 | 实施与验收 |
| --- | --- |
| 权限及家属查询 | 现行版按岗位、工作分院和绑定亲属关系授权，并提供用途脱敏和受控审计。试点时对接机构身份源，扩展家属查阅范围。验证换岗、离职、撤销家属授权后，旧会话无法继续读取目标记录。家属端可查看经授权的服务、任务、医嘱、用药记录。 |
| 收款与通知 | 在支付服务商沙箱接入微信/支付宝，建立账单号、商户流水、通知与日终对账单的映射。校验签名和商户身份，处理重复、乱序回调与退款。通过账单、到账、次日对账三方一致的样本后开通机构商户。 |
| 文书识别与回填 | DeepSeek OCR 的原件、转录及人工复核记录可按住户查阅。有位置框或置信度的行可供核对，其余字段由授权人员对照原件人工补全后签认。验证错误姓名、药名或单位不会自动覆盖原档案。 |
| 辅助建议与主动照护 | 按日常照护、物资和经营三类注册建议来源、算法版本、依据记录及复核节点。演进项包括照护计划和交班初稿、多源告警去重分发、消耗趋势与异常领用、欠费及收费异常、只读经营问答。用已标注案例分别记录误报、漏报、采纳和驳回，逐条追踪实际处理结果。 |

**退出条件**为授权矩阵、沙箱对账、模型建议的人工复核与撤回机制全部完成验收。PDF 第 6 页的响应速度表述属于材料中的预期效果。机构须先记录“事件发生至首次响应”的指标口径及基线，试点后再测量变化。

## 第四阶段 · 对外报送与医养协同

**前置输入**为当地民政、区域健康档案、公卫、长护险及医联体提供的字段字典、接口协议、测试环境、机构资质与授权范围。

1. **民政报送**。将本地草稿映射到指定版本的数据集，保留校验、审核、送出、受理、退回和重报的版本链。用缺字段、重复提交及远端超时验收。同一笔报送的回执必须关联原快照。
2. **区域健康档案及转诊**。建立区域授权映射、来源机构、授权有效期及撤销处理。验证出院评估衔接、既往档案调阅、重复身份核对、跨机构授权到期。
3. **公卫与长护险**。串联筛查建档、分级评估、随访干预和效果评价。按当地要求对齐服务项目与资格，抽验每笔服务能追溯到评估、授权、执行及复核。
4. **机构上线**。使用脱敏副本演练迁移、故障恢复、备份还原、账期重算与回执重放。护理、财务、监管接口方各自签认核对样本后，再安排真实账户和数据切换。

## 后续开发顺序

新增场景先写一条可复现的验收记录，注明发起角色、前置状态、操作、成功后的关联记录、重复或失败后的预期。再定义领域动作、输入口径和审计信息，接入页面与持久化。支付、OCR、模型、扫码设备、区域健康平台与民政接口分别保留本地输入样本和适配层。逐个用提供方的沙箱验证后替换演示实现。

每次完成一个可验收的增量，将对应代码、需求说明和验证结果一并提交并推送到 ReFac 的项目仓库。用同一提交编号记录评审与回归结果。
