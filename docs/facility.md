# 安康家园分院、建筑与房间工作台

安康家园本部当前有一栋主楼。本版按六个使用楼层登记，楼层标号依次为 1、2、3、5、6、7。“6 层且没有四楼”采用跳号理解，现场人员可据门牌核验。楼层记录、排序和房间标识相互独立，扩建可在本部增设楼栋，也可为新分院建立独立的楼栋、楼层与房号。

## 总部启用分院

1. 总管理员在「房间工作台 → 空间管理 → 新增分院」填写名称和选填地址。切换到新分院，依次添加楼栋、楼层、房间及床位。不同分院可以各有「主楼」和「101 房」。
2. 在「账号与权限 → 新增员工」或编辑现有员工，选择工作分院和岗位。总部需要跨院处理业务的账号选择「全机构」。升级前的员工保留原有授权，旧楼栋和旧入住意向归本部。已知楼层、房间、床位、文档及会话的编号继续有效。
3. 分院岗位可在授权范围登记接待、入住、查房、护理、医疗档案及关联住户的费用。长者转院后由现床位所在分院接续查阅，其档案和文档随人保留。退住后由最后所在分院查阅。跨院转床由具备接待权限的全机构账号办理。
4. 分院员工管理员只能为本人范围内的员工分配自己可委派的权限。普通员工的分院选择在服务端生效，直接打开另一院房号、医疗原件、预警或 Agent 历史编号也会重新校验。
5. 物资、全机构排班、监管报送、机构支出及全机构用药规则维护由总部管理。分院可依业务权限查询本人分院长者的操作记录，也可筛选房间和员工。亲属账号仍按绑定长者单独授权。
6. 同一运营机构内的分院共用机构设置、账套和全机构备份。销售给独立客户时应为每个客户使用自己的部署、数据库、密钥与备份目标。

## 护士查房

1. 登录后进入房间工作台，选择分院、楼栋和楼层。平面图上的房间热点和房号列表共享同一房间编号，两种入口打开相同的床位及在住人员。
2. 输入姓名中的任何一个字或部分房号。全角数字、半角数字、空格及房号后缀在本地处理。例如“１０１号房”可以找到 101 房。当前分院的结果给出分院、楼栋、楼层和房号，同名长者或不同楼栋的相同房号按实际位置列出。
3. 进入房间查看床号和在住姓名。办理入住、转床或退住后重新查询，结果依据当前业务记录生成。一次筛选默认返回 12 间、最多 30 间，命中更多时返回 `hasMore`，可选择楼层或补充搜索字缩小范围。

初次迁移将旧库的 101–104、201–204、301–304 等既有房号关联到对应楼层。原 24 张演示床位、19 位在住长者以及转床和护理记录保留原有编号。5、6、7 层可逐间登记实际房号。初始平面图使用可点击的示意坐标；机构登记测绘坐标后接口返回 `registered`。床位关系统一取自业务主库，图上位置用于导航。

## 房间与导览 API

「全部床位」可按房间号、楼层与房号、照护区域或平面图位置排序，支持楼栋和父子区域筛选。「区域设置」内每栋楼各自维护区域树，可覆盖整层或单间，房间的显式划分优先。给护工分配多个区域用于照护职责匹配，查阅权限仍由账号授权决定。

新版演示数据可用 `python3 -m tools.seed_modern_demo --db .local/new-demo.sqlite3` 在新路径创建，包含两栋楼、28 张床、八个照护区域及三餐和早晚巡查的初始派发。

| 接口 | 输入和最小返回 |
| --- | --- |
| `GET /api/facility` | 分院名录及地址，楼栋所属分院，楼层编号、授权范围内房间数及管理能力。总管理员还可查看待定位的旧床位。 |
| `GET /api/facility/floors/{id}` | 一层的房号、房间编号、矩形坐标、床位数和在住数。平面示意只包含当前账号可查看的房间。 |
| `GET /api/facility/rooms?bedCount=1&limit=3` | 查询最多三间单人间，返回当前授权范围内的房型、位置和占用数。可叠加现有院区、楼栋、楼层或房间范围。 |
| `GET /api/facility/rooms/{id}` | 单间床号、状态、当前在住长者姓名及档案编号。 |
| `GET /api/facility/search?q=兰&campusId=…&buildingId=…&floorId=…&roomId=…&limit=12` | 区域参数可省略或叠加。优先返回精确匹配；单字、子串和房号均在机构服务端匹配，无模型调用。结果只含匹配名及定位字段。 |
| `GET /api/facility/tour?campusId=…&buildingId=…&floorId=…&roomId=…` | 楼栋公共区、楼层公共区与房间级环境视点，包含照片或全景媒体地址、标题、位置、展示次序。可遍历整院或选定范围。收到 `awaiting_media` 表示当前范围内暂无已发布的影像。 |

私域房间目录与检索向拥有照护、接待、临床或基本档案权限的工作人员开放。亲属登录后可看已发布的环境导览。影像导览端点只返回环境元数据。运营方应选用获准展示、已处理住户隐私的现场素材。

## 总管理员扩建与导览维护

使用现有登录会话、`POST /api/commands`、最新的工作区 `revision` 和下列动作。每个动作在同一机构事务内更新，并写入机构操作日志。新增床位即可在既有入住业务中选择。

| 动作 | 表单与验收 |
| --- | --- |
| `facility.addCampus` | 提供分院 `name` 和可选的 `address`，再次请求目录取得 `campusId`。 |
| `facility.addBuilding` | 提供 `name` 和 `campusId`。旧客户端省略分院时登记到本部。再次请求目录取得新楼栋编号。 |
| `facility.updateCampus`、`facility.renameBuilding` | 分别按 `campusId` 更新名称及地址，或按 `buildingId` 修改楼名。历史发放的床号继续使用，地图及导览按稳定编号读取最新地址和名称。 |
| `facility.addFloor` | 提供 `buildingId` 和整数 `number`。每栋按实际楼层编号独立管理。 |
| `facility.addRoom` | 提供 `floorId`、`number`、`ward`；可带 `bedCount`（0–12）、`dailyRate`（元）。已登记几何的楼层，新增房间须提供图内坐标。 |
| `facility.addBeds` | 为现有房间提交 `roomId`、`count`、`dailyRate`。新旧床位属于同一房间；不同楼栋相同房号的床单可通过楼栋及楼层区分。 |
| `facility.updateRoom` | 提交 `roomId` 及目标 `bedCount`（0–12）。通过「房间详情 → 编辑房型」办理。减配停用空床并保留原编号和历史，增配先恢复可用的旧床。新建床位日价由有财务权限的经办人设置。 |
| `facility.linkBed` | 旧库中门牌无法明确定位时，根据现场核对结果将 `bedId` 绑定到同护理区的 `roomId`，保留其原编号和入住关联。已定位床位拒绝再次绑定。 |
| `facility.setLayout` | 提交 `floorId` 与完整的 `rooms` 数组，每项含 `roomId,x,y,w,h`。坐标原点为左上角，单位为图幅的百分比。整体核对同层归属、范围、遗漏和重叠，通过后一次发布。可附加经核准的环境平面底图地址 `planMediaUrl`；仅获单间授权的账号看到所授权房间的图形。 |
| `facility.setScene` | 选择 `buildingId`、`floorId` 或 `roomId`，填写 `title`、`kind`、`mediaUrl`、`sortOrder`。同一目标可以有多个命名视点。重发同名视点会更新媒体。 |
| `facility.withdrawScene` | 按 `sceneId` 撤下视点，之后的环境导览列表同步更新。 |

楼层接口的 `vector` 返回可缩放矩形和图幅。未登记实际坐标时由系统生成示意。保存经核对的布局后，平面图使用登记坐标。管理员可以把「维护授权房间的房型和楼层矢量平面图」授予指定员工。只授权单间时，可修改这个房间的房型。保存全层矢量布局需要该楼层的完整权限。健康助理可以打开相同入口，最终改动由经办人确认。

经过机构授权的现场照片、全景图及平面图，通过 `python3 manage_storage.py --db .local/workspace.sqlite3 import-tour lobby.jpg /path/to/lobby.jpg` 导入加密数据库，再登记同源地址 `/tour-media/lobby.jpg`。服务端按当前登录人和视点或楼层权限读取。导入的原件随数据库快照保存。外部托管可通过 `NH_TOUR_MEDIA_ORIGINS` 指定获准的 HTTPS 源；快照保存外部 URL，外部图像由托管方备份并控制访问。[加密与备份](storage.md)

## AI 范围与首批验收

Agent 与人工入口复用同一组查询、房间与楼层编号。区域解析器至少需要一项分院、楼栋、楼层或房间编号，返回实际覆盖的稳定房间、床位与在住人员编号，供宿主在调用业务工具之前裁剪数据。输出简报只需引用对应标识。

每个机构数据库自动生成独立持久的站点编号。预留给受信身份提供者的 `facilityScope` 包含 `institutionId` 与可选的 `campusIds`、`buildingIds`、`floorIds`、`roomIds`。传入多个维度时取交集，显式空集合不给予该维度任何权限。普通请求只能在当前授权内进一步缩小搜索范围。账号管理持久保存工作分院。部署可通过已认证的宿主策略追加楼栋、楼层和房间限制。

| 迭代 | 可重放验收 |
| --- | --- |
| 建立楼栋关系 | 从既有数据库启动两次，核对房间和床位编号、住户与历史记录无损；按任意名字片段和全角房号定位。 |
| 验证扩建 | 新增一栋楼及同名 101 房，登记一张床，办理实际入住，再按名字找到新房。转床后旧房清空。 |
| 签认布局与导览 | 核对机构测绘资料，提交全层布局并点选每间房；发布入口、公共区和房间的获准照片，按路径浏览并撤下一项。 |
| 约束 Agent | 用限层、限房及空授权分别查房，核对检索、详情与区域解析返回一致的人员编号；用亲属账号验证仅能调阅环境场景。 |

在独立样本上运行 `python3 -m unittest discover -s tests -p test_facility.py -v`。[院区模块](../platform_core/facility.py) · [回归用例](../tests/test_facility.py)

分院隔离回归可运行 `python3 -m unittest discover -s tests -p test_campuses.py -v`，涵盖旧库升级、重复房号、分院授权、医疗原件、预警和历史 Agent 任务。

## 从档案分配床位

正式入住的合同默认无期限，选择有期限时填写到期日。只有填了到期日的合同才进入「到期续住」提醒。办理正式入住时可选每月 1 至 31 日作为账单日，默认取入住日。原来已经登记的合同期限继续有效。

1. 在「照护业务 → 长者档案 → 新建长者档案」选择分院和档案类别。新档案未占床。参与试点前已有的历史咨询可在名册底部逐条转为档案。
2. 默认名册展示未入住的新档案以及尚待确认或取消入住的试住档案。输入姓名、姓氏或档案号即可搜索全部状态，列表底部的「查看全部档案」可直接浏览在住及归档老人。发现同名归档时先打开原档案核对身份；重新入住时建立本次独立档案，旧账单和原住期继续关联原来的档案号。
3. 选择档案并点击「办理入住」。确认页显示床位所在分院、楼栋、楼层和床号。床位管理的「全部床位」与「楼层平面图」共用同一分配逻辑，点击空床会打开可搜索的档案选择器。在住长者转床时须核对原床位和新床位，两个床位及床头卡在同一事务内更新。[电脑端转床确认实拍](previews/admission-transfer.jpg)
4. 退住后立即释放床位，档案进入「归档老人」。补录旧资料时可以直接选择归档类别；若需先上传纸质原件及完善个人资料，可先建立未入住档案，人工录入后选择「封存为归档老人」。归档资料仅供查阅，个人诊疗与照护资料不进入识别、巡查或协作 Agent。
5. 按北京时间从退住或归档日期计算 365 天，满期后自动清理日常档案姓名、家庭和联系资料，并退出日常检索。原件、已出具账单、临床依据和审计凭证按既有保管策略通过档案号追溯；加密快照有单独的保管期限。旧库退住日期缺失或无效时，页面提示「原退住日期待核实」，不推算期限。具有入住权限的人员可凭原件补登日期，若已满 365 天，确认后即按期清理。在线导入在提交前检查到期状态，防止用早期快照重新公开已清理的日常档案。

## 试住与回访

1. 总管理员在「机构设置 → 试住约定」选择默认时长和一次性总价。默认时长为 3 天 2 夜，例如 24 日入住，预计 26 日结束。经办人在「长者档案 → 试住管理」选择档案、床位和本次约定。免费试住应明确填 0 元。确认试住后占用床位，同时生成一次性试住账单。这份档案继续显示在「长者档案 → 档案名册 → 待入住档案」，直到经办人确认或取消入住。
2. 试住成功时点「确认入住」，核对月付账单日和合同期限，原床位、档案和试住凭证接续使用。提前转正的月费从试住总价已覆盖的住宿期结束后开始，以免同一晚重复计费。[试住管理桌面实拍](previews/trial-stays.jpg)
3. 尚未登记决定时，试住床位保留到最后一天结束。以上例计算，27 日零时起（北京时间）系统自动退床，经办员工在右上角铃铛看到「试住期满待确认入住」。关机期间错过的到期记录会在下次开机补办。此时可重新选择空床确认入住，月费从实际转正日开始。
4. 未转正式时点击「取消入住」，填写原因、回访负责人和计划回访日。保存后释放床位、归档，并同步派发回访。被指定员工点击右上角铃铛中的「待我办理的试住回访」，提交回访方式、结果、沟通反馈和后续安排。未完成的任务可由有入住权限的人员改派，已签署的报告可在试住管理中回查。

## 意向客户与接待排班

未登录访客可以从登录页进入「访客咨询与预约参观」，也可直接打开机构域名下的 `/visit`。每个院区共用同一套入口，访客自己选择目标院区。[访客页面实拍](previews/visitor-reception.jpg)

| 来源 | 登记与跟进 |
| --- | --- |
| 宣传页「请给我回电」 | 访客填写或自动填充自己的手机号，确认同意后提交。系统比对机构已登记的家属、员工及在住长者号码，并按院区去重。公开回执一致。 |
| 宣传页「申请参观」 | 可使用已有联系电话。期望日期与时刻供接待人员参考，电话确认后再占位。 |
| 电话来询、直接到访 | 员工从「机构运营 → 意向客户 → 手工登记」选择来电或到访，填写真实发生时间。同一客户多次来电各自留痕。 |
| 已入住或不再需要回访 | 按已登记的长者本人号码等资料识别已入住客户，停止电话回访并释放未执行的回访预约；客户主动来电、参观仍可登记。员工也能记录「暂无意向」停止跟进。 |

「接待时间表」显示选定院区当天各席位与实际来电记录。回访和参观共用席位，时间按北京时间计算。每段 30 分钟，默认每个院区同时接待 1 位。总管理员或具备接待及员工管理权限的人员可以调整为 1–32 席。尚有预约的席位须先处理预约再停用。

员工通话核实后，从客户记录或空闲席位选择开始、结束时间，勾选电话确认后提交。每一位客户全程占用同一席位。例如，甲占第 1 席 16:00–16:30、乙占第 2 席 16:30–17:30 时，两席都无法承接 16:00–17:00 的整段预约。接待后可填写实际时间与反馈，再归档查阅。改期、取消和归档均留有记录。[双席排班实拍](previews/lead-schedule.jpg)

### 意向客户号码与归档

接待人员在「意向客户」看到本分院号码。尚无匹配联系人的号码标为「新客」，已有关联的号码列出登记的长者、床号、关系和联系人。点击「查看记录」可以核对授权留号、主动申请或员工登记的来源、通话、排期及反馈。已有在住长者的免回访规则继续生效。

归档时保存当时的床位与联系人关系。满 365 天后清理该接待个案的联系方式、反馈和排期，仅留加密库内的号码匹配标记与停止回访意愿，避免旧线索再次触发电话回访。
