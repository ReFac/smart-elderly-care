# 2026-11-25 性能与功能回归

在代码基线 `6f0df71` 和本次优化后的工作树上分别测试。使用临时加密数据库、虚构账号和模拟供应商，运行中的演示机构没有参与压测。

## 工作台性能

同一台 Debian 12 KVM 虚拟机分配 2 vCPU、2 GiB 内存，禁用交换空间。测试数据含 1 名 Owner、109 名员工、520 个关联亲属账号和 1,000 个仅注册客户账号。6 个并发客户端交替用 Owner、护士、亲属身份读取工作台全量数据、版本和助理导航版本。每种角色的每个端点采样 100 次，耗时包含建立回环连接和读完整响应。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 混合请求吞吐（请求/秒，含所有响应状态） | 110.87 | 196.32 |
| 900 次请求中的 HTTP 200 / 503 | 898 / 2 | 900 / 0 |
| Owner 工作台 p95 | 365.19 ms | 199.51 ms |
| 护士工作台 p95 | 68.62 ms | 53.61 ms |
| 亲属工作台 p95 | 44.73 ms | 33.56 ms |
| 服务进程 CPU 时间 | 9.95 s | 5.97 s |
| 服务进程生命周期峰值 RSS | 147.16 MiB | 144.01 MiB |

工作台生成账号目录时，同一角色的多个操作会共用权限。现在每份操作清单对每种权限计算一次，并跳过缺少员工引用字段的记录。宿主机对同一份加密库做单路对照，每角色各读 100 次。Owner 的生成加序列化中位耗时从 56.02 ms 降至 22.50 ms。Owner、受托管理员与亲属各自的完整响应在两个版本中长度和 SHA-256 均一致。这个数据集的 Owner 全量响应仍有 1,126,264 字节，表内时延按回环连接测得。

静态 JS、CSS 支持浏览器用 ETag 复核。登录 HTML、业务 JSON、医疗图片及原件继续使用 `no-store`。在宿主机复取入口及静态导入涉及的 117 份脚本和样式，未变内容的响应正文从每次 1,077,247 字节降为 0。虚拟机另测首页直接引用的 24 份资源，从 213,335 字节降为 0。两次测量均保留了每份资源的 HTTP 请求和响应头。替换同长度、同修改时间的静态文件后，浏览器可拿到新内容。

## 并发转床与过载

- **200 床读写。** 180 位在住长辈、20 张空床，两个读取客户端与两个经办请求并行。20 轮争床中，每轮先以同一修订号争同一张床，再读取最新修订并改选空床。共 40 次成功转床、20 次修订冲突（409）和 20 次已占床拒绝（400）。120 次并行读取均成功。42 次快照中，长辈、床位和房号的关联均一致，最终新增 40 条转床记录。成功转床 p95 为 24.62 ms，服务进程峰值 RSS 为 82.24 MiB。
- **32 路上传。** 同时提交 1–4 MiB 的模拟 OCR 文件，模拟识别耗时 1.2 秒。2 次获处理，30 次收到明确的过载响应（503），期间 16 次健康检查均成功，p95 为 0.9 ms。服务峰值 RSS 为 67.7 MiB。该测试衡量上传保护与服务可用性，识别速度由模拟器设定。

## 复跑

安装项目的 [Python 依赖](../requirements-storage.txt) 和 Poppler，在允许监听本地回环端口的 Linux 环境中，从仓库根目录运行以下命令。后续复跑使用简体中文机构和语言无关的性能场景。性能工具会创建并回收临时机构库。[仓库测试约定](../AGENTS.md)

```bash
export NH_DEPLOYMENT_LANGUAGE=zh-CN
python3 -W error::ResourceWarning tests/run.py -v
npm --prefix clients/desktop test
python3 tests/perf_workspace.py --clients 6 --samples 100
python3 tests/perf_beds.py
```

### 复跑 200 床持续负载

在分配了 2 核、2 GiB 内存且关闭交换空间的 Linux 虚拟机中，提供一个尚不存在的私有结果目录。从受测版本的源码根目录运行以下命令，`--source-revision` 填该版本的完整 Git 提交号。

```bash
python3 tests/soak_200_beds.py /var/tmp/eldercare-200-bed-run --source-revision "$(git rev-parse HEAD)"
python3 tests/soak_report.py /var/tmp/eldercare-200-bed-run /var/tmp/eldercare-200-bed-report.md
```

默认实跑 86,400 秒，覆盖 200 床、180 位合成在住长辈。测试按分钟采集服务内存，每 4 秒并发读取三个工作台接口，每 3 分钟登记一笔可逐条核对的体征。预设三餐和早晚巡查覆盖全院，另设每小时一批两人巡查。持续负载结束后，服务额外保留 60 秒供最后一个调度周期完成，再核对所有到期回执、加密备份和独立恢复结果。正式结果可分享生成的 Markdown 和同名数值 CSV；私有结果目录包含合成业务库及其测试密钥。
