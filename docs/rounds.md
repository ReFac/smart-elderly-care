# 语音协作与定时巡查

## 护士的一班

1. 在右上角打开「健康助理」，按住说话，松开后自动转写。勾选自动发送可以直接提问，也可使用键盘。涉及创建工单或通知时，先确认执行人和内容。[语音识别和计量](media.md)
2. 在长辈详细档案中打开「近期变化与建议」。按日期阅读今天和昨天的起居、三餐和活动；展开段落下的「查看依据」可查到日期、原件或活动记录编号。集体用餐由工作人员核对参加名单后才进入简报。有个人进食观察时会显示实际记录，例如“早餐喝了半碗小米粥”。仅有餐单和出席确认时显示“参加了早餐，餐点有小米粥、鸡蛋”。
3. 点击「生成简报」可立即更新。「生成设置」可为该长辈选择跟随机构、定时或手动。DeepSeek 将该长辈的已核实事实整理成段落，每条事实必须保留日期与出处。缺失的餐次和观察留白；只有护理人员确实记录过时才描述睡眠、食量或身体是否如常。临床人员可另看已核实的跌倒和复核后的身体变化；凭证或人员范围变化后会重新核对。
4. 护理岗位在简报下展开「护理交班工具」可核对待办顺序。有两类以上可排序的当日事项、机构套餐可用且账号持有照护及助理权限时，提供「请 DeepSeek 排列核对顺序」。确认后只发送事项类别代号，按本期套餐计量。
5. 打开右上角铃铛的「今日巡查提醒」，或「预警与确认 → 巡查提醒」查看授权区域内的跟进事项。家属在本人账号收取订阅时约定的简版消息，仅含当天照护安排的数量和经核实的明显咳嗽增加提示。投递要求长辈逐人授权并由家属主动订阅，个人餐单、观察原话和身体变化详情仍按员工岗位授权展示。[家属授权和撤回](dossier.md)

长辈本人账号获授「个人生活与健康档案」后，可在「长辈服务」阅读已生成的生活简报。本人版提供经过核实的参加情况、可直接分享的餐食描述及重要变化。照护人员的自由备注、原始凭证和操作人信息留在员工档案。打开本人页只读取已生成的内容。

## 机构设置与运行

总管理员在「机构设置 → Agent 巡查」选择开关、间隔、默认生成方式和当日推送时间。初始值为每 60 分钟巡查、每日 17:30 站内提醒，使用北京时间。间隔范围为 5 至 1440 分钟。页面显示下次和上次巡查时间。关闭浏览器后，只要机构服务仍在线，后台仍会工作。到达推送时刻后，自动模式会核对当日最新资料，即使常规巡查间隔尚未到，也能发出跟进提醒。服务重启后接续当前业务日待办；错过的历史日期不会伪造观察结果。

每个长辈的作业分别提交，生成记录绑定当日、当前入住床位和证据。员工查看简报时重新检查临床权限、分院及床位。员工提醒和家属收件各有独立的收件条件；同一天重复巡查会复用已有投递。当前推送渠道为站内收件。

## 个人咳嗽趋势

在档案中选择「登记观察」，填写日期、自然小时、该小时实际覆盖分钟、复核后的事件数、稳定的设备来源及个人归属依据。每人每个自然小时提供一个合计，重复提交同一条记录会复用凭证。更换设备、推理阈值或观察方法时，使用新的来源标识。简报提示明显变化时，可展开「查看咳嗽变化的观察依据」核对逐小时的覆盖时间、来源和复核时间。

巡查比较当前入住床位、相同钟点、相同来源和相同个人归属方式的观测。每小时至少覆盖 30 分钟、本日合计至少 60 分钟，且过去 7 日内有至少 3 个可比日时，才计算相对个人历史中位数的变化。各日按今天观察的时段权重换算成次/小时。当频率达到个人历史中位数的 1.5 倍，并且每小时至少增加 2 次时，生活简报才提及咳嗽。该规则用于筛选值得人工关注的变化。临床判断由医护人员结合现场观察完成。

| 可选接入 | 适合的工作 | 使用条件 |
| --- | --- | --- |
| Google YAMNet | 在院内设备对单声道音频识别包括 Cough 在内的环境声音，输出候选片段。仓库提供本地转换工具。 | 发布的模型卡标注 Apache-2.0。用于产品分发时保留许可和适用声明。模型无法识别是哪位住户发声。[Google 官方调用示例](https://developers.google.com/edge/mediapipe/solutions/audio/audio_classifier) · [模型与许可](https://huggingface.co/litert-community/MediaPipe-AudioClassifier-YAMNet) |

### 在本机运行 YAMNet

观察工具独立于语音指令栏。它读取操作员指定的 WAV，在本机计算，输出计数、覆盖分钟、模型校验值和筛选阈值。它不会开启病房麦克风或自动建立个人健康记录。请使用获准的个人佩戴录音，或由现场人员核实归属。多人病房的环境声、电视和相邻人员均可能产生误报。

以下示例适用于有 Python 3.12 的 Linux 电脑。模型固定为 Google 的 MediaPipe float32 v1，工具在推理前校验 SHA-256。依赖和权重保存在 Git 忽略的安装目录。

```bash
mkdir -p .local/acoustic
python3.12 -m venv .local/acoustic/runtime
.local/acoustic/runtime/bin/python -m pip install ai-edge-litert==2.4.0 numpy
curl -fL https://storage.googleapis.com/mediapipe-models/audio_classifier/yamnet/float32/1/yamnet.tflite -o .local/acoustic/yamnet.tflite
.local/acoustic/runtime/bin/python observe_cough.py /path/to/authorized.wav \
  --model .local/acoustic/yamnet.tflite --start 2026-11-24T09:00 --threshold 0.50
```

音频须为 16 kHz、单声道、16 位 PCM，并处于同一自然小时内，时长为整分钟。工具把连续超过阈值的重叠窗口计为一个候选。0.50 是初始筛选分数；噪声可造成误检，密集的连续咳声可能合并。输出中的 `reviewed` 始终为 `false`。护士核对后在档案登记实际结果，同时在来源标识中记录模型、设备和阈值。样机用一分钟合成静音验证了本地执行和零候选输出，护理场景的灵敏度与误报率还需用获准样本验证。

## 对接入口

| 入口 | 用途 |
| --- | --- |
| `GET /api/rounds/settings`、`POST /api/rounds/settings` | 总管理员读取或更改机构巡查策略。 |
| `GET /api/rounds/residents/{id}` | 当前授权范围内的生成方式和最近简报。 |
| `POST .../{id}/generate`、`POST .../{id}/mode` | 生成当前简报或更改该长辈的策略。 |
| `GET/POST .../{id}/observations` | 临床岗位查看及登记已复核的逐小时观测。 |
| `GET/POST .../{id}/priorities` | 查询或确认进行一次 DeepSeek 事项排序。GET 需带 `reportId` 查询参数。 |
| `GET /api/rounds/inbox` | 查看当前员工可见的提醒。 |
| `POST /api/agent/voice/transcriptions` | 转写发起人确认发送的语音任务目标。 |

巡查写入请求携带前次读取的 `revision`，可附 `comment`。岗位变化、范围变化、转床、重复提交和并发在后端重新校验。家属走独立门户，消息不包含员工原文、模型排序和临床记录。
