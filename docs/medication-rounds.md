# 床旁服药核对

[文档导航](README.md)

护工进入房间工作台，点击「核对本房服药」，按床位顺序逐人核对。要查某位长辈，打开其档案中的「服药核对」，即可看到个人名单和最近 60 条签认。健康助理接受明确的文字或语音报告，例如「101、102 房的老人早晨都服药了，除了 101 房 2 床的张某，因外出未服」。房间或床号有重名时，系统会请经办人手动选房。语音转写和文字共用同一份逐人确认表。

选择实际服药情况。长辈未服药时填写原因，有具体观察时间也可以补上。时间留空时，凭证仍记录观察时段和实际签认时间。一句话可以报告早晨、中午和晚上三个时段。系统只列出已经开始的时段，每位长辈每个时段都要单独确认。点击「暂跳过」不会留下签名。

| 登录权限 | 可以签认的内容 |
| --- | --- |
| 照护 | 老人是否已服、未服的现场原因、床旁观察时间 |
| 照护和临床 | 在签认时逐项勾选同一老人、同一时段、已经到点、经过复核并待执行的医嘱 |
| 护士复核 | 在「照护服务 → 健康体征」查看未服报告，填写核实和处置记录 |

经办人口述「今日无需服药」时，系统保留原话，交给护士复核。原有医嘱的状态保持不变。已到时的多条医嘱需要经办人逐项核对。未勾选的医嘱继续留在用药台账。

## 打印和扫描

打开在住长辈的档案，点击「床头卡」打印。二维码包含机构访问地址、当次分床卡号和床位标签。手机扫码打开机构网站，完成登录后直接核对该床。已登录的床旁工作台也支持扫码枪输入或手动输入八位卡号，原有条码继续可用。卡号随分床更新，转床或退住后旧卡失效。

从旧库恢复资料时，如果有分床流水却缺少卡号，沿用当时的机构级分床序号。旧库完全缺少个人分床流水时，只有在住档案与床位占用人互相匹配，系统才从独立号段补发，并保存两者编号、补发时刻和补发依据。

请先确认手机能访问二维码中的地址。实际部署时通过服务的 `--public-origin` 指定可访问的 HTTPS 域名。安装基础依赖时会安装生成二维码的 `qrcode` 包。

## 事务和数据

`POST /api/medication-rounds/preview` 接受 `roomId`、`residentId`、`cardCode` 或 `text` 中的一种。可选的 `region` 进一步限定分院、楼栋、楼层或房间。文本解析通过已配置的 DeepSeek 通道提取原话中的对象和例外。服务端在当前账号的授权住户范围内匹配，核对口述解析后的名单，再返回带校验值的逐项草稿。

每次点击确认只提交一个 `care.confirmMedRound` 命令。服务端从当前会话确定签认人和签认时间，提交前再次核对长辈是否在住、床位、所选区域、医嘱和执行时刻。按「老人、机构当地日期、时段」去重，签认凭证、勾选的医嘱执行、未服复核记录在同一事务保存。独立凭证随加密快照备份，导入旧快照时保留现有签认。
