# 床旁服药核对

护工在房间工作台点击「核对本房服药」即可按床位顺序核对。老人档案中的「服药核对」打开个人名单和最近 60 条签认。健康助理接受明确的文字或语音报告，例如「101、102 房的老人早晨都服药了，除了 101 房 2 床的张某，因外出未服」。房间或床号有重名时，系统会请经办人手动选房。语音转写和文字共用同一份逐人确认表。

经办人选择实际情况、填写未服原因，并可补充观察的具体时间。未填写具体时刻时，凭证保留观察时段和实际签认时间。早晨、中午和晚上可以在一句话中报告，系统会为每一位老人、每一个已经开始的时段分别提供确认。点击「暂跳过」不会留下签名。

| 登录权限 | 可以签认的内容 |
| --- | --- |
| 照护 | 老人是否已服、未服的现场原因、床旁观察时间 |
| 照护和临床 | 在签认时逐项勾选同一老人、同一时段、已经到点、经过复核并待执行的医嘱 |
| 护士复核 | 在「照护服务 → 健康体征」查看未服报告，填写核实和处置记录 |

「今日无需服药」以经办人报告的原话归档，提交护士复核；原有医嘱继续保持其当前状态。已到时的多条医嘱需要经办人逐项核对。未勾选的医嘱继续留在用药台账。

## 打印和扫描

在在住老人的档案中打开「床头卡」并打印。二维码包含机构访问地址、当次分床卡号和床位标签。手机扫码打开机构网站，完成登录后直接核对该床。已登录的床旁工作台也支持扫码枪输入或手动输入八位卡号，原有条码继续可用。卡号随分床更新，转床或退住后旧卡失效。旧库有分床流水但缺卡号时，沿用当时的机构级分床序号。旧库完全缺少个人分床流水时，只有在住档案与床位占用人互相匹配，系统才从独立号段补发，并保存两者编号、补发时刻和补发依据。手机需要能访问二维码里的地址，实际部署时通过服务的 `--public-origin` 指定可访问的 HTTPS 域名。安装基础依赖时会安装生成二维码的 `qrcode` 包。

## 事务和数据

`POST /api/medication-rounds/preview` 接受 `roomId`、`residentId`、`cardCode` 或 `text` 中的一种。可选的 `region` 进一步限定分院、楼栋、楼层或房间。文本解析通过已配置的 DeepSeek 通道提取原话中的对象和例外。服务端在当前账号的授权住户范围内匹配，核对口述解析后的名单，再返回带校验值的逐项草稿。

每次点击确认只提交一个 `care.confirmMedRound` 命令。签认时重新验证在住关系、床位、选择的区域、医嘱与执行时刻。签认人和签认时间来自服务器会话。按「老人、机构当地日期、时段」去重，签认凭证、勾选的医嘱执行、未服复核记录在同一事务保存。独立凭证随加密快照备份，导入旧快照时保留现有签认。
