# 最近改动与撤销

「最近改动」按业务版本展示过去 60 天的成功提交。打开一行可以查看执行时间、经办人、变更说明、受影响记录、字段原值和新值。长辈详细档案右上角的「最近改动」在同一窗口显示该长辈的记录，可返回刚才查阅的栏目。以房间或长辈为入口时，工作台使用稳定的业务编号筛选，同号房的记录各自归属于发生时的院区和房间。护理时间线上的半小时合并属于展示设置，每次工单登记仍保留自己的版本和办理人。

## 确认和核对

1. 在对应业务界面提交，核对确认窗中的对象和改动。可填写最多 240 字的变更说明，例如「家属核实后更正常住地址」。取消时业务数据和历史版本保持原值。
2. 确认后由业务服务器重新校验账号权限、区域和当前工作版本。业务内容、审计摘要和字段差异在同一个写事务中保存。执行失败会回滚该事务。
3. 在「最近改动」进入详细记录。普通员工可看本人办理且现岗位仍可访问的记录。获得审计授权的员工可核对本人业务和区域内获准的事项。总管理员可查全机构。若一项改动混合了不同权限的字段，系统也按当前权限隐藏可能引用这些字段的自由说明，并从搜索中排除这些说明。账号密码只记录凭据更换事件。医疗原件和音频以原件标识、字节数或摘要关联，原文件由加密档案保管。
4. 对可逆的变更，选择「撤销」并确认。系统在写入前重验岗位、分院、原值及后续引用。成功后新增一项补偿提交，原提交记录保留撤销版本。两人同时撤销相同版本时，只有一项能提交。

## 可撤销的范围

| 办理事项 | 回退行为 |
| --- | --- |
| 长辈档案、护理时间线设置 | 逐字段还原。后来由他人更新的其他字段保留。撤销涉及家庭资料的改动仍须具有亲属资料权限。 |
| 待执行护理工单、入住接待、物资建档、排班 | 可撤回仍与原提交一致且没有下游引用的新增条目。已产生质检、库存流水或引用凭证时，详情显示原因。 |
| 日常照护工单完成登记 | 可更正误记的普通执行状态。系统核对类型、现入住床位和后续凭证。涉及医嘱、用药及其他临床处置时，须按相应业务流程办理。 |
| 已确认的日常护理语音申请 | 更正工单完成状态，原申请进入「已撤销」终态，保留原确认人和确认时间。重新办理须由工作人员发起新操作。 |
| 界面设置、识别开关、备份保留策略、分院资料及楼栋更名 | 由获授权的管理人员撤回仍符合当前约束的字段。还原备份策略会递增配置版本；已经按此前策略清理的副本须从其他保存位置恢复。 |
| 医疗原件、已有临床处置、支付和对外签发 | 保留提交和凭证供核对，后续在相应模块登记更正或接收回执。 |
| 批量导入业务快照 | 管理员可从导入详情定位执行前的保护点，在备份页面预检并执行新的恢复。导入前版本可继续查阅。 |

## 保留及升级

精确字段历史按提交时间滚动保留 60 天。历史记录在业务提交和启动时清理，查询也使用同一时限。原有业务审计、不可变医疗原件、法定业务凭证和手工快照各自遵循对应模块的保留策略。过去生成的加密快照保留创建当时的内容，从中重启业务库时重新应用 60 天时限。升级前的审计只有时间、经办人和摘要，近期仍可查看，无法从这些摘要推算历史字段值。独立的网盘授权、进程锁、登录会话和临时下载票据由各自的部署或安全机制管理。[加密备份与保留设置](backups.md)

## 接口

| 请求 | 用途 |
| --- | --- |
| `GET /api/history` | 按版本倒序分页，支持 `residentId`、`roomId`、`actorId`、`before`、`limit`。用 `q` 搜索本人可见的摘要及变更说明，输入 `v123` 精确定位版本。用 `day=YYYY-MM-DD` 筛选北京时间的某一天。 |
| `GET /api/history/{revision}` | 返回当前账号可看见的变更说明、前后差异、关联目标及撤销条件。 |
| `POST /api/history/{revision}/undo` | 请求中传入当前工作版本 `revision` 和可选的 `comment`，成功返回新的修订号。 |

## 院内 Agent 复核

办理入住、转床、结构化档案、长护险、收费、收款、物资、账户及备份时，服务端先在提交事务中检查关键约束。床位按长辈核对唯一占用，收费逐行复算数量、单价、减免、实收和余额，长护险按正式文书及日期核对办理阶段。冲突会阻止该笔写入。

成功提交后，后台向 DeepSeek 提交业务域、操作类型和校验凭据中的项目名称，为经办人生成一份可阅读的复核说明。账户凭据、医疗原件、人员姓名和银行卡付款码留在机构侧。详情分别显示数据校验项目、云端状态和回执。重试使用持久队列，云端请求计入机构套餐。精确记录与复核说明保留 60 天；归档老人继续按原件封存。
