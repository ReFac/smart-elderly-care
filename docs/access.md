# 账号、授权与机构设置

首次创建机构时，直接在服务所在交互终端为 `owner` 设置口令，支持在自动部署时通过密钥环境变量 `NH_OWNER_PASSWORD` 注入初值。初始化完成后可移除该变量。已有账号的口令摘要与会话在本次就地升级中保留。

## 岗位及可见范围

| 身份或模板 | 初始授权 | 可配置项 |
| --- | --- | --- |
| 总管理员 | 机构全部业务、账号、审计、界面和已购 AI 套餐用量 | 创建员工、调整授权、停用与恢复账号、重置密码、绑定经核实的亲属关系 |
| 院长 | 接待与档案、照护、仓储、财务、排班、报送、建议、设备模拟及授权业务日志 | 在员工详情勾选该院长的具体工作权限 |
| 护士 | 档案、照护、体征与用药、医疗图片读写、预警复核及语音申请确认 | 可独立收回预警复核、医疗图片写入或语音确认 |
| 护士长 | 护士岗位权限，另可核对集体活动参加名单并签认 | 总管理员也可给指定代班员工单独勾选「核对集体活动参加名单并签认」。所有签认均受院区和房间范围约束。 |
| 护工 | 基本档案、照护和语音申请确认 | 可单独保留发起申请，将确认授权给值班人员 |
| 财务 / 自定义 | 财务与报送 / 从空权限开始分配 | 获授权的业务数据随角色一起生效 |
| 长者本人 | 绑定本人档案、环境导览与个人中心 | 可单独开通「查看本人的生活简报、时间线与健康简介」。照护工单、已完成服务和用药记录另行授权。身份和绑定对象自创建后固定。 |
| 亲属 | 本人账号及明确绑定的长者姓名、本人可完善的资料 | 总管理员核验关系后创建，登录名与绑定长者不可在线改绑。更换授权对象时停用旧账号并新建绑定。 |

管理页面的岗位模板用于预填勾选项。新院长模板包含语音输入与「向全体员工发布通知」。既有账号可在这里单独授权。发布机构通知需要全机构范围，员工通过顶部铃铛查看；家属仅能查看本人授权的服务消息。服务端以实际勾选的权限做决定。医疗归档写入自动附带原件读取，语音确认同时要求目标照护权限，运营建议的可见性还需匹配来源业务域。工作台只下发当前账号可查看的集合和基本档案字段，未授权账号无法从快照读取管理配置、医疗原件或其他亲属资料。普通员工无法创建账号或修改自身授权。

操作日志按登录账号和变更发生时的房间信息记名。「操作日志」需有审计权限，员工还需有对应业务权限，总管理员可跨业务查询。历史日志缺少可验证的建议类别时，员工须同时拥有三类来源授权。

### 员工管理与个人中心

总管理员进入「账号与权限」，给指定员工勾选「在本人业务权限内管理员工账号」。该授权单独发放，已有院长与历史账号不会自动获得。受托人员只能查看和管理业务授权在本人范围内的普通员工，可以创建账号、调岗及启停。受托人员的管理目录过滤其他管理员、本人、家属及超出范围的员工。账号可选择「全机构」或指定工作分院。受托管理员授予的分院须在自己可管理范围内，部署方提供的楼栋、楼层和房间限制与账号分院取交集。跨院档案、医疗原件、语音确认和 Agent 历史均在服务端复核。[分院授权及操作](facility.md)

管理人员可在编辑表单中预览未保存的岗位配置。只读接口 `POST /api/access/preview` 接收 `kind`、`role`、`permissions` 和可选的目标 `id`，返回服务端计算的模块和可办理操作。保存时再次检查双方授权。变更审计记录实际授予与收回的项目。

右上角姓名菜单与院内服务导航均可进入「个人中心」。每个人看到自己的账号、岗位、有效入口及授权。通过 `account.changePassword` 提交当前密码与新密码后，此账号所有设备都会退出。家属默认可以完善本人的亲属资料，总管理员按经核验的关系为该账号勾选「查看已完成的照护服务」后，才可查看其绑定长者最近 30 条已办服务，包括完成日期、计划日期、时间及服务名称。

总管理员可按绑定账号分别授予三项院内服务。已完成服务清单限近期 30 条。照护工单授权可查看进度和执行日期，并对已完成的一次服务评价一次。用药查阅授权可见经复核的医嘱、计划时间和实际执行时间。撤销授权后，同一账号的既有会话按新权限读取；同一长者的其他亲属独立授权。工单和医嘱表每组 30 条，可向前翻阅本人的完整历史。长者本人使用「长者服务」入口，亲属可在「家属服务」维护自己的身份与联系方式。

用药配伍规则的发布与停用需同时持有临床和专业规则维护权限。专业规则维护权由总管理员单独发放。正式量表的临床依据、原件及特殊情况按岗位查阅，普通照护人员可登记生活需求、查看照护等级与派工安排。文书 OCR 回填需医疗原件查阅、档案写入及临床复核权限。动态档案摘要的签认需医疗原件查阅和临床权限。

### 班次交接

有照护权限的人员可查询 `GET /api/care/handover-recipients`。结果给出其他在岗照护账号的编号、姓名和登录名，用于区分同名员工。创建和签收均走带 `revision` 的业务命令接口。

| 命令 | 提交字段 | 服务端记录 |
| --- | --- | --- |
| `care.handover` | `assigneeId`、`note`，可选 `residentId` | 验证接班账号当前授权，保存提交人、接班人、时间及工单数量快照。交接双方都具有临床权限时，快照包含待复核体征数量，查看时按当前读者权限显示。 |
| `care.acceptHandover` | `handoverId`，可选 `note` | 已指定的接班人登录后可签收一次。保存实际签收账号、时间和备注。单人交班的创建及签收日志分别记录当时的房间。 |
| `care.withdrawHandover` | `handoverId`、`reason` | 原交班人填写原因后可撤回待签收记录。若同时发生签收与撤回，仅先成功的一方生效，回执与审计同事务保存。 |

照护人员可查阅交班台账。顶部待办只统计分配给本人且尚未签收的记录。历史版本仅填写姓名的交班条目保留为历史记录。

## 常见操作

1. 进入「账号与权限 → 新增员工」，填写姓名、登录名和账号本人用于首次激活的邮箱或手机，选择岗位、职责和权限。创建后由使用人在登录页申请验证码并设置口令。受托员工只看本人授权范围内的员工。总管理员可按姓名、岗位职责、登录名或绑定长者搜索所有账号，单独筛选员工、长者本人、亲属及待激活账号。
2. 对已登录员工调整勾选项。每次读取或提交均重新取最新授权，前端重新载入即可同步导航。
3. 停用账号或本人通过验证码设置密码后，该账号所有设备的会话即时结束。实际使用者在「个人中心」核实恢复邮箱或手机号，或通过登录页「首次设置 / 找回密码」接收 OTP。
4. 在「机构设置」更改平台名称、机构名称、主题及导航模块可见性。导航隐藏属于展示偏好，员工的真实访问权限仍由「账号与权限」决定。
5. 在「机构设置 → 平台 AI 套餐」查看本机构的套餐、到期日、额度和已用 token。平台运营方核实付款后开通。各机构账号均无填写凭据、换模型或发放额度的入口。具体操作见[平台套餐说明](provider.md)。

## 员工劳动合同与工资日

1. 总管理员或获授员工管理权限的经办人在「账号与权限」找到员工或护工，点击「合同与工资日」。可管理的账号沿用机构、分院和岗位授权范围。
2. 点「留存合同新版本」上传签署的 PDF、JPEG 或 PNG 原件，单份上限为 8 MiB。登记签订日、合同起始日及固定或无固定期限，可另填合同编号。确认后会保留原件、版本、经办人及时间，可逐版打开核对。
3. 点「设置工资日」选择每月 1 至 31 日。员工目录会标明约定日期，档案展示下一个工资日。例如约定 31 日，四月显示 30 日，五月仍为 31 日。这里记录约定发薪日期，实际发放需要财务办理。
4. 员工在「个人中心 → 我的劳动合同与工资日」只读查阅本人资料。停用账号后原会话立即失效，授权管理人员仍可查阅留存的版本。合同原件和工资日随机构加密快照保存，在线导入旧快照时会核对当前已留存的原件。[备份恢复操作](backups.md)

## 会话与验证

密码采用独立随机盐与 scrypt 派生，服务端使用 12 小时有效的不透明令牌，数据库只保存令牌摘要。使用浏览器的会话 Cookie 时，属性由 HTTP 入口设置。单个账号在 15 分钟内连续出现 8 次错误后暂时限制登录。注册过的账号独立计数，未知登录名共享失败预算。

在独立数据库上测试首次登录、撤销、角色投影、图片授权依赖、DeepSeek 数据隔离、登录限速和员工建议审计范围。

```bash
python3 -m unittest discover -s tests -p test_access.py -v
```

## 本人激活、改密和找回

管理员在账号目录核对使用人和邀请地址。已创建的待激活账号可更正邀请地址，更正时作废原验证码。首次收件人输入验证码并设置密码后，管理员只能管理权限和启停，账号本人负责更新恢复方式。每个账号使用独立随机盐和 scrypt 摘要；当前密码、验证码明文、SMTP 口令均不进入客户端账号列表及业务日志。

个人中心首次绑定时，输入当前密码并核验新联系方式。更新已有渠道需同时持有当前密码、原渠道验证码和新渠道验证码。设置密码会结束全部登录会话。每个验证码只可使用一次，有效期 10 分钟，最多尝试 5 次；同一账号申请至少间隔 60 秒。找回页的统一响应不会公开账号或邮箱是否已登记。

### 配置投递

在服务进程环境中配置邮件服务器。SMTP 凭据由部署方通过系统密钥设施注入。发件邮箱需获得邮件服务商授权。

| 环境变量 | 含义 |
| --- | --- |
| `NH_SMTP_HOST`、`NH_SMTP_FROM` | 邮件服务器主机名和已授权发件邮箱。 |
| `NH_SMTP_TLS`、`NH_SMTP_PORT` | 默认 `ssl` / 465，使用加密升级的服务器可选 `starttls` / 587。两种方式均校验 TLS 证书。 |
| `NH_SMTP_USER`、`NH_SMTP_PASSWORD` | 邮件服务要求认证时注入用户名和授权口令。 |

尚未开通邮件投递或短信适配器的实例会在界面显示现状。短信供应商确定后，在服务构建时传入 `Store(..., code_senders={"sms": sender})`。同步回调 `sender(destination, code)` 将验证码提交至服务商；投递被拒应抛出 `OSError`。不得打印或持久化验证码。适配器固定在部署端，网页请求不能指定服务商地址。

升级会移除现行数据库内旧版可读取的初始口令。升级前已经导出的加密快照仍代表当时的数据；此前一直沿用旧版初始口令的总管理员，可在完成邮箱或手机绑定后通过验证码更新口令。新版恢复程序会清除旧包中的可读取初始凭据。

旧账号可用原口令登录并在「个人中心 → 验证联系方式」完成绑定。对于尚未绑定任何恢复方式且遗忘原口令的首位总管理员，以及无人值守首次部署时未指定初始口令的机构，可由持有机构库及其密钥的宿主机运维人员协助完成首次绑定。启动命令的环境中也要配置投递渠道；在本机终端输入实际收到的验证码后，再从登录页设置本人密码。命令不会显示现有口令或绕过已绑定渠道。

```bash
python3 manage_storage.py --db .local/workspace.sqlite3 enroll-owner --channel email
```

就地升级会删除旧版首次口令的可恢复存储。在线导入业务快照保留现有账号和验证渠道。离线灾备到新主机时，旧会话、待验证的请求全部失效，历史联系方式暂停用于找回，防止快照重启后将验证码发送给已经换手的邮箱或 SIM。本人可凭已有密码登录重新核验；仍待激活的邀请由账号管理员核实后重新登记。既有加密历史备份在原期限内保管，旧格式包仍可能包含历史首次凭据，请独立保管离线恢复材料并通过验证码更换该旧口令。
